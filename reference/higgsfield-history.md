2. **사건을 빼서 풀었다.** C#2는 문이 닫히는 환경 사건을 지운 판이 확정됐다.
3. **참조 권한을 문장으로 나눴다.** "시작 이미지가 카메라·방·빛의 유일한 권한, 인물 참조는 얼굴·옷만, 소품 참조는 재질·모양만".
4. **소품 크기를 장면에서 가져왔다.** 흰 배경 봉지 참조 → 상체만큼 커짐 → 확정 영상의 1초 프레임을 잘라 만든 요소로 교체 → 해결.
5. **좌우를 물건으로 썼다.** "신발장 쪽 손", "파란·흰 무늬 쿠션 옆 자리", "담요가 걸린 팔걸이의 반대쪽 끝".
6. **반응의 크기를 양 끝으로 닫았다.** "굳음이 크거나 한숨이면 실패, 반응이 없어도 실패".

## 6. 확정된 프롬프트의 공통점 vs 안 된 프롬프트의 공통점

| 확정된 쪽 | 안 된 쪽 |
|---|---|
| 시작 이미지가 장면을 다 정함, 프롬프트는 그 뒤의 움직임만 | 프롬프트로 장면·카메라·장소를 새로 만들게 함 |
| 사건 1~3개, 5~10초 | 한 클립에 장소 3개, 대사 6줄, 30초 |
| 참조마다 권한 한 줄 | "레퍼런스" 한 단어, 또는 썸네일을 통째로 |
| 좌우·위치를 물건과 거리로 | "오른손", "근처에", % 좌표 수십 개 |
| "일어나지 않는 것"을 구간별로 명시 | 금지어를 길게 나열(오히려 불러옴) |
| 한 번에 한 가지 고친 판 | 여러 가지를 동시에 고친 판 |
| 확정본에서 출발한 수정 | 처음부터 다시 쓴 프롬프트 |

## 7. 다음 프로젝트에 그대로 적용할 것

1. 생성은 프로젝트 폴더 안에서만. 컷마다 하위 폴더.
2. 공통 에셋(인물 시트, 장소 마스터, 그림체 기준)을 먼저 확정하고 컷에 물린다.
3. 새 장소는 이미지로 먼저 확정한 뒤 영상으로.
4. 영상은 480p·짧게 확인 → 확정 → 1080p. 하루 같은 컷 영상 10회 초과 = 정지 신호.
5. 이미지 1k 한 장씩. 동시 여러 장 금지.
6. 15블록(실사) / 4문단(배경) 중 하나로 쓰고, 참조 권한·물건 기준 좌표·상태 머신을 넣는다.
7. 2회 실패 → 사건 줄이기·샷 쪼개기·직접 편집·후반 중 하나.
8. 확정되면 즉시 `decisions.md`·`asset-registry.md`에 job ID와 함께.
9. 업스케일은 최종본에만.
10. 세션 끝마다 핸드오프에 생성 횟수·크레딧.

규칙은 `kit/skills/`에, 사건별 근거는 `reference/error-registry.md`에 있다.
