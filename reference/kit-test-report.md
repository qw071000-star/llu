## 2. 원본 대조 감사에서 고친 것

- **장소:** 원본 템플릿 01~12 중 역방향·새 공간·레이아웃 변환·시대 교체·소품 파생·사물 편집 공식이 빠지거나 한 줄로 줄어 있었다. `location-view.md`, `location-edit.md`로 나눠 원본 영어 문장을 그대로 넣었다. 좌우 기준이 원본(화면 기준)과 키트(장소 기준)로 갈려 있던 것을 "프롬프트는 화면 기준, LIGHT LOCK·랜드마크는 장소 기준 + 화면 대응 줄"로 정리했다. 원문 10(잠금 + 180° 회전 모순)을 검사기가 통과시키던 것을 FAIL로 바꿨다.
- **인물 시트:** 성숙한 골격·`no babyface`, 나이 든 인물의 손, 일관성 잠금 전문, 고스트 마네킹 변형 B, 목둘레 세 곳, CHANGE·LEFT 목록 맞추기, 의상 참조의 `Do not transfer the face`, 실존 인물 금지를 되살렸다. 시트는 처음부터 2k(원본 고정 규격).
- **연기:** 몸 네 축(호흡), 서브텍스트, 평가의 순간, 말(사이·음량), 장면 적응의 불변 핵심, 앙상블, 아틀라스 15종, 보내기 전 점검을 넣었다. 비트(2~4)와 사건 수(1~3)의 충돌을 "비트는 같은 행동 안의 전술 변화"로 풀었다.
- **영상:** 도는 동작 수정값이 원본과 달랐다(1.5초 → 원본 3초, 머리→어깨→발). 15블록 고정을 깨던 "짧은 판"을 지웠다. 컷 나누기, 시간·영역을 한정한 참조, 음성 파일 연결, 샷당 렌즈 하나, Required 3~5개를 넣었다.
- **구조:** 검사 실행법이 지도 밖 스킬에만 있던 것, Docs·지식 모드의 컷 카드 위치, 재렌더 방식 두 가지, 비어 있던 정본 우선순위, 폴더 ID 중복을 고쳤다.

### 실제 Claude Code 실행 (real1~real4)

r1~r6은 플레이어에게 "SKILL.md를 직접 열라"고 시킨 모의 시험이었다. 그다음부터는 시험 작품 폴더에 키트를 실제로 설치했다(`.claude/skills/`, `CLAUDE.md`가 `instructions.md`와 `context/` 두 파일을 불러옴). 그 상태로 `claude -p`에 **사용자 말만** 넣었다. 실행기는 `tests/agent-eval/real_run.py`, 대본은 `real-chains.json`(49체인, 87턴)이다. Higgsfield만 시뮬레이션이다.

| 회차 | PASS | 부분 | FAIL | 그 회차 뒤에 고친 것 |
|---|---|---|---|---|
| real1 | 47 | 20 | 1 | 검사기 실행 허용 `project-files/settings.json`, 질문 범위, 여는 파일 정리 |
| real2 | 74 | 13 | 0 | 태그 꺾쇠 유지, 옆모습 손, 시작 이미지 없을 때 질문 범위 |

- 스킬은 SKILL 도구로 부르기보다 `context/routing.md`가 가리키는 파일을 직접 읽는 방식으로 쓰였다. 내용은 같다.
- 질문 턴은 항상 읽히는 `must-ask.md`만으로 나왔다. 프롬프트 턴에 단계 파일을 열었다.
- real3부터 남은 부분 판정은 대부분 이미 있는 규칙을 모델이 어긴 경우다. 다른 컷 카드를 형식 예시로 연다, 질문 턴에 acting을 연다 같은 것들이다. 회차마다 몇 건씩 생겼다 사라진다.

**남은 한계:** 플레이어도 채점자도 Claude다. Claude 앱에서 스킬이 저절로 열리는지, Docs 정본 읽기·쓰기는 시험 밖이다. Sonnet은 형식을 보려고 다른 컷 카드를 여는 버릇이 r3b에서도 한 번 남았다.

한 작업에 2만 2천 자 안팎(약 1만 토큰)이다. 한 대화에서 컷 하나를 처음부터 끝까지 하면 3~4만 자까지 쌓인다. 단계가 바뀌면(에셋 → 퍼스트 프레임 → 영상) 핸드오프를 남기고 새 대화로 넘기는 편이 낫다.
