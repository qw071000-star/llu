  - 일부러 틀린 5개는 걸려야 한다.

### 대화 흐름 시나리오 판정

프롬프트가 아니라 Claude의 행동을 보는 시나리오다. 키트대로라면 할 일을 따라가고, 사용자 요구와 맞는지 봤다.

**S01 새 작품 시작** — 첫 메시지: "시골 정류장에서 할아버지와 손녀 나오는 단편 시작하자"
1. 정본이 비어 있으므로 새 작품으로 판단하고 `project-setup`을 연다. 시작 문구는 필요 없다.
2. 질문 12개를 기본값과 함께 한 번에 묻는다. "바꿀 것만 답해 주세요"라고 쓴다.
3. 답을 받으면 정본 초안을 쓴다. Higgsfield 폴더 구성을 보이고 "제가 만들까요?"라고 묻는다.
4. 정본 위치를 정하고, 지침의 "이 프로젝트" 세 줄을 채워 달라고 한다.
- 판정 ✔
- 주의: 질문 12개는 길다. 기본값이 있어 대부분 "그대로"로 끝나지만, 처음 쓰는 팀원에게는 부담일 수 있다.

**S10 정보가 빠진 영상 요청** — "C03 영상 만들어 줘. 할아버지가 손녀에게 가방 건네는 거"
1. 인물·장소·소품 요소와 시작 이미지는 정본과 에셋 대장에서 채운다.
2. 비는 칸은 카메라 위치·높이, 렌즈, 인물별 시작·끝 위치, 동선, 시선, 액션 타이밍, 대사다.
3. 이것들을 §0 질문 형식대로 한 번에, 제안값과 이유를 붙여 묻는다.
4. 답은 컷 카드 [4]~[6]에 적은 뒤 프롬프트를 쓴다. 시작 이미지가 없으면 퍼스트 프레임부터 만든다.
- 판정 ✔
- 한계: 추측해서 채웠는지는 검사 스크립트가 다 잡지 못한다(N1은 좌표 문장·mm만 걸림). 컷 카드 [4]~[6]에 답이 기록됐는지로 사람이 확인한다.

**S12 생성 → 확인 → 판정**
1. §1 점검 5개를 거친 뒤 `count: 1`, `folder_id`를 넣어 보낸다. 정해진 형식으로 알리고 턴을 끝낸다. 기다리지 않는다.
2. "됐어" → 그 job만 한 번 조회한다. 지시 항목별 ✔/✘를 적고 "승인할까요, 거절할까요?"라고 묻는다.
3. 사용자 말에 따라 처리한다.
   - "이상해" → 원인과 수정안을 말하고 거절할지 묻는다.
   - "별로" → `거절` 폴더로 옮기고 컷 카드 [11]에 적는다.
   - "다시 만들어" → 바꿀 한 가지를 "전 → 후"로 보인다.
- 판정: 수정 후 ✔

**S14 저장 폴더가 없는 컷**
1. 컷 카드 [2]와 폴더 표에 C05가 없다. 그래서 구성(`C05 [진행]` / `승인` · `거절`)을 보이고 "제가 만들까요, 직접 만드시겠어요?"라고 묻는다.
2. 만든 뒤 시간 초과가 나면 `list_folders`로 확인하고 다시 만들지 않는다.
3. 새 폴더 ID를 기록한다.
- 판정 ✔

**S15 새 대화에서 "C03"만 입력**
1. 컷 세션으로 판단한다. 그 컷의 정본 줄과 에셋만 읽는다.
2. Higgsfield 컷 폴더의 상태와 마지막 핸드오프를 먼저 확인한다.
3. 시작 보고를 세 줄로 한다: 판단 근거, 읽은 것, 지금 할 일.
- 판정 ✔
- 한계: "이전 대화 검색" 도구가 없는 환경에서는 핸드오프 로그에만 기댄다. 핸드오프를 안 남기면 이어지지 않는다.

## 5. 시험하지 못한 것과 남은 위험

- **같은 모델이 쓰고 같은 모델이 따라 했다.** 키트를 쓴 Claude가 시나리오도 실연했으니, 키트에 적히지 않은 것을 무의식적으로 채웠을 수 있다.
- **실제 Claude 앱 동작은 보지 않았다.**
  - 스킬이 설명만 보고 알아서 열리는지
  - 커넥터 권한
  - Docs 정본 읽기·쓰기
  - 이전 대화 검색
- **실제 생성 품질은 모른다.** 프롬프트가 가이드대로인 것과 결과가 좋은 것은 다르다.
- **15블록 프롬프트는 인물이 둘이면 5,000자에 가깝다.** 인물이 셋 이상이면 넘을 수 있다. 그때는 샷을 나누거나 장소·스타일 문장을 줄인다.
- **검사 스크립트는 형식만 본다.** CHANGE와 ONLY CHANGE의 내용이 같은지, 사건 수가 몇 개인지는 사람이 본다.

**다음 단계 제안 (비용 0)**
1. 실제 Claude 앱 프로젝트에서 한 컷을 "프롬프트만 만들어"로 진행한다.
2. 이 보고서의 S09·S10과 비교한다. 질문을 했는지, 15블록을 지켰는지, 고정 설명문을 그대로 썼는지 본다.
