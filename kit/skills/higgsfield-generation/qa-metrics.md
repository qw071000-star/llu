# 숫자 검수 — 사용자가 분석을 원할 때만

숫자가 "통과"여도, 사용자가 "비어 보인다"고 하면 그 말이 판정이다. 숫자는 원인을 찾는 데 쓴다.

| 지표 | 재는 법 | 기준 예 (나부코 수채 배경) |
|---|---|---|
| 전체·구역 밝기 | 0~1 평균 | 컷마다 목표 범위를 정한다(예: 0.45~0.50). 이웃 컷과 비교한다 |
| 요소 위치 | 화면 % (위에서, 폭) | 크롭 띠·가림 구역 안인지 밖인지 |
| 가장자리 비율 | 에지 픽셀 비율 | 수채는 2~8%. 13~22%면 질감이 과밀하다(해칭, 로우폴리) |
| 구조 일치도 | 기준 이미지와 SSIM | "그대로 유지" 편집이면 0.9 이상 |
| 하이라이트 | 거의 흰 픽셀 비율 | 0.1% 이하(수채) |
| 카메라 움직임 | 광학 흐름으로 누적 확대·이동 | "약 2배"를 요청했는데 3.56배가 나온 적이 있다. 요청량의 절반으로 쓴다 |
| 속도 균일성 | 1초당 변화량 | 일정해야 한다. 끝 프레임을 넣은 30초 영상은 끝에서 5배로 빨라졌다 |
| 질감 떨림 | 연속 프레임 차이 | 나무나 새가 갑자기 생기거나 사라지지 않는지 본다 |

**다른 컷과 비교할 때 보는 것**
- 시점과 구도가 겹치는가
- 빛의 방향과 밝기가 튀는가
- 소품 상태가 이어지는가
- 마지막 프레임과 다음 컷 첫 프레임이 이어지는가
