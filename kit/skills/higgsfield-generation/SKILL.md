# Higgsfield 생성 운영

## 1. 생성 전 점검 (모두 예여야 보낸다)

1. 사용자가 이 생성을 지시했는가. "프롬프트 만들어"는 생성 지시가 아니다.
2. 저장할 `folder_id`가 정해졌는가(§2).
3. 해상도가 확인용인가. 이미지는 1k, 영상은 480p에 짧게. 고해상도는 사용자가 확정한 뒤에만 쓴다.
4. 처음 쓰는 모델·설정이면 `get_cost: true`로 견적을 봤는가.
5. 위험 목록과 프롬프트 전문을 먼저 보였는가.
6. 검사 스크립트를 통과했는가. 코드 실행이 되는 환경에서만 한다.
   - 프롬프트를 파일로 저장하고 이 스킬 폴더의 `check_prompt.py`를 실행한다.
   - 실행: `python3 check_prompt.py --kind video|image 파일 --refs 붙일참조수 [--must-include 고정문장파일]`
   - FAIL은 고친다. WARN은 고치거나, 그대로 둘 이유를 한 줄 적는다.
   - 점검표를 다시 읽는 것보다 빠르고, 과거 실수를 기계적으로 잡는다.

## 2. 저장 위치

**어디서 찾나:** 컷 카드의 `[2] 저장 위치` → `asset-registry.md`의 폴더 표 → 사용자에게 묻기, 이 순서로 찾는다.

- 모든 생성에 `folder_id`를 넘긴다. 폴더 없이 만들면 프로젝트 밖에 저장된다.
  - 실제 기록: 영상 126번 중 프로젝트에 남은 것은 39개였다.
  - 하루 영상 26번 중 2개만 남은 날도 있었다.
  - 무엇을 왜 만들었는지 추적이 안 되면 같은 실수를 반복한다.
- 기본 설정(`get_preferences`)이 프로젝트를 자동으로 만들어도 기대지 않는다. 폴더를 명시한다.

**폴더가 없을 때:** 아래 구성안을 이 작품에 맞춰 보이고 묻는다.

> "제가 만들까요, 직접 만드시겠어요?"

```
「작품명」 (Higgsfield 프로젝트)
├─ 00 에셋 / 인물 · 장소 · 소품 · 그림체     ← 확정된 공통 에셋만
├─ C01 [진행]                                ← 새 결과물은 여기 = 검토 대기
│   ├─ 승인
│   └─ 거절
├─ C02 [대기]
└─ 99 시험·보관                              ← 시험 생성, 교체된 옛 승인본
```

- 구간이 있는 작품은 `1구간 / C03 [진행] / 승인·거절`처럼 한 층을 더 둔다.
- **Claude가 만들 때:** `create_folder`로 컷 폴더를 만들고, 그 안에 `승인`과 `거절`을 만든다.
  - 시간 초과가 나도 다시 만들지 않는다. `list_folders`로 생겼는지 먼저 확인한다(중복 생성 방지).
- **사용자가 만들 때:** 정확한 폴더 이름을 알려 준다. 끝났다고 하면 `search_folders`로 ID를 찾는다.
- 새 폴더 ID는 `asset-registry.md` 폴더 표(Claude Code) 또는 "정본 갱신" 블록(Claude 앱)에 적는다.

## 3. 요청을 보내고 턴을 끝낸다

영상은 몇 분, 이미지도 수십 초가 걸린다. 그동안 상태를 반복 조회하면 조회할 때마다 대화 전체가 다시 처리되어 토큰이 크게 샌다. 기다림은 사용자에게 맡긴다.

**보내기**
- 하나를 만들 때는 `generate_image` 또는 `generate_video`를 `count: 1`로 쓴다. 진행 상황은 위젯이 알아서 보여 준다.
- 여러 개는 사용자가 한 번에 지시했을 때만 `generate_*_batch`로 보낸다. 받은 job ID 목록을 남긴다.

**보낸 뒤 이 형식으로 쓰고 바로 끝낸다**

```
보냈습니다.
- [컷] [무엇] · [모델] · [해상도·길이] · job `[앞 8자리]`
- 저장: 「작품」/[폴더]
- 볼 점: [지시 항목 2~3개]
완성되면 알려 주세요. 분석이나 개선점, 다른 컷과의 비교가 필요하면 말씀해 주세요.
```

**하지 않는다**
- `jobs_wait`나 상태 조회를 반복하지 않는다.
- 같은 요청을 다시 보내지 않는다.
  - 전송 시간 초과도 마찬가지다. 앞 요청의 결과를 모르는 상태에서 다시 보내면 중복 과금된다.
- 기다리는 동안 다른 생성을 덧붙이지 않는다.

**사용자가 "됐어", "완성됐어"라고 하면**
1. 그 job만 한 번 조회한다.
   - 하나면 `job_display`나 `jobs_wait`(`timeout_seconds: 0`)로 본다.
   - 배치면 `jobs_wait`(0) 한 번 뒤 `show_generation_by_ids`를 한 번 쓴다.
2. 아직 진행 중이면 "아직 진행 중입니다. 완성되면 알려 주세요."라고 하고 끝낸다.
3. 완성됐으면 짧게 확인한다.
   - 지시 항목마다 ✔/✘를 적는다(3~5줄).
   - 그리고 "승인할까요, 거절할까요?"라고 묻는다.
4. 숫자 측정, 원인 분석, 다른 컷과의 비교는 사용자가 원할 때만 한다(`qa-metrics.md`).

**사용자가 "기다렸다가 봐 줘"라고 하면**
- 이미지는 `jobs_wait`(15초)를 최대 4번까지만 쓴다. 그래도 안 끝나면 끝낸다.
- 영상은 기다리지 않는다. 이유를 한 줄로 말한다.

## 4. 상태 표시

| 사용자 말 | 결과물 상태 | Claude가 할 일 |
|---|---|---|
| "좋아", "이걸로", "픽스", "확정" | 승인 | `승인` 폴더로 옮기고, 정본에 job·날짜·한계를 적는다 |
| "별로", "아니야", "다시", "이상해" | 거절 | `거절` 폴더로 옮기고, 이유 한 줄 + 원인 + 수정안을 말한다. 다시 만들지는 않는다 |
| "나중에", "일단 둬" | 보류 | 컷 폴더에 그대로 두고 컷 카드 [11]에 적는다 |
| 새 승인본이 생김 | 대체됨 | 옛 승인본을 `99 시험·보관`으로 옮긴다 |

**옮기는 법**
1. `list_project_assets`(`folder_id`는 컷 폴더)로 해당 job의 `placement_id`를 찾는다.
2. `move_project_asset`으로 `승인` 또는 `거절` 폴더로 옮긴다.

**컷 상태**
- 단계: `대기` → `진행` → `검토` → `승인`. 중간에 `보류`가 될 수 있다.
- 컷 폴더 이름 끝(`C03 [승인]`)을 `rename_folder`로 바꾼다.
- `shot-list.md`의 상태 열에도 같은 말을 쓴다. 폴더 이름은 보이기 위한 사본이고, 정본은 `shot-list.md`다.

**거절 이유는 짧게 남긴다.** 컷 카드 [11] "이전 시도"에 `job — 거절 — 이유`로 적는다. 다음 시도의 위험 목록이 여기서 나온다.

## 5. 검수와 재시도

- **보고:** 만든 것(ID), 맞은 것(✔), 미달(측정값이나 눈으로 본 것), 판단, 다음 선택지 순서로 쓴다. 질문은 하나만 한다.
- **숫자:** 잰 것만 숫자로 쓴다. 재지 않았으면 "추정"이라고 쓴다.
- **화면 사진:** 사용자가 보낸 모니터 촬영 사진은 비교에만 쓰고 참조로 붙이지 않는다. 원본 파일을 받는다.
- **재시도 한도:** 같은 이미지에서 같은 실패는 2회까지. 3회째 전에 멈추고 승인을 받는다.
- **같은 핵심 실패가 연속 2회, 또는 최근 4회 중 3회 나오면:** 문장을 더하지 않는다. 다음 중 하나로 바꾼다.
  1. 샷을 둘로 나눈다.
  2. 사건을 뺀다.
  3. 개념을 단순하게 만든다.
  4. 직접 편집(합성)한다.
  5. 후반 작업으로 넘긴다.
- **후반으로 넘길 것:** 영상 모델이 지키지 못한 것들이다.
  - 정확한 이동 거리, 정확한 등장·퇴장 타이밍
  - 작고 어두운 풀의 흔들림, 별 반짝임, 그림에 칠해진 빛줄기의 회전
  - 새 떼처럼 작은 반복 객체의 경로
  - 디졸브, 색 맞춤

## 6. 해상도 단계

1. 확인용: 이미지 1k, 영상 480p 짧게.
2. 사용자가 확정한다.
3. 확정본만 고해상도(이미지 2k, 영상 1080p)로 같은 프롬프트·같은 참조로 다시 뽑는다.

주의할 점:
- 고해상도로 다시 뽑는다고 더 좋아지지 않는다. 1080p로 다시 뽑자 없던 결함(우편 투입구)이 생긴 기록이 있다.
- 업스케일은 수채·필름 질감을 지운다. 쓰기 전에 묻는다.
- 4k는 지시받은 것만 만든다.

## 7. 크레딧

**비용이 몰리는 곳:** 대부분 영상 반복 생성이다.
- 실제 기록: 순지출 8,671 크레딧 중 「어머니와 고등어」 씬 1이 5,356이었고, 그중 Seedance 영상이 4,168이었다.
- 이미지는 장당 2.5~4.5로 싸지만, 8일에 204장이 쌓였다.

**관찰된 단가 (크레딧/회 — 실제 값은 견적으로 확인한다)**

| 모델 | 단가 |
|---|---|
| Seedance 2.5 | 15~144 (보통 21~24, 1080p 한 컷 108) |
| Kling 4.0 | 3~81 (보통 10) |
| GPT Image 2.5 | 0.5~16 (보통 2.5) |
| Nano Banana Pro | 0~4 |
| Seedream 5.0 Pro | 1.25~3 |
| Topaz 영상 업스케일 | 3~73 |

**아끼는 법**
1. 새 장소나 구도는 영상이 아니라 이미지로 먼저 확정한다.
2. 한 번에 여러 장을 뽑지 않는다. 한 장을 보고 결정한다.
3. 같은 날 같은 컷 영상이 10회를 넘으면, 그 자체를 경보로 보고 멈춘다.
4. 확정본을 "조금 더 좋게" 다시 돌리지 않는다.
5. 핸드오프에 그 세션의 생성 횟수와 크레딧을 적는다.
