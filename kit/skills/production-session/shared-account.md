# Shared-account operation

Applies when `decisions.md` §7 says `운영 방식: 공용 계정`: one Claude account and one Higgsfield account used by several people in turns (often through several Claude projects that share one canon). Docs edits and Higgsfield jobs all show the same account, so **nothing records who did what unless the canon does**. Do not ask the user to set up anything else; just follow these rules.

1. **Who.** The user's first message names them (`나는 지수`). If missing, ask once per conversation. The name goes into: the cut list `담당` cell, the handoff header, the OK card `승인` line.
2. **Claim before work.** Read the cut's `상태` and `담당` first. If another name holds the cut in `진행` or `검토`, say so in one line and ask before working on it (the cut folder name `[진행]` is the same signal). If the cell is empty or the user's own, write the user's name in `담당`.
3. **Writes.** The lead is named in `decisions.md` §7 `총괄:` (ask once if missing). `decisions.md` and `asset-registry.md` are lead-only (`SKILL.md` §1): if the speaker is not the lead, do not edit them or show an edit block for them; put the request in handoff [5] for the lead. A cut session writes its own row (`담당`, `상태`, confirmed jobs), its own card, OK cards, handoffs. Everything else goes to handoff [5].
4. **OK cards are append-only.** Never edit an approved card or its prompt. A correction is a new line under that card: `정정(날짜 · 이름): [무엇을 → 무엇으로 · 이유]`. A replacement is a new take: new card, and the old card and approved result move to the log and `99 시험·보관` (`higgsfield-generation` §4 "Superseded"). Before writing any card, find its title (`3-1 시작 이미지`, `3-1 영상`); if it exists, ask: correction or new take?
5. **Start image and video are saved as a pair.** Approving a start image writes the card `3-1 시작 이미지` with its prompt verbatim; the video card's `시작 이미지:` line gives that job and card title. A video approval whose start image has no card: write that card first (prompt from `get_project_asset_prompt`, else ask the user to paste it).
6. **Cut numbers are stable.** Once a cut has a job, a folder or a card, never renumber it. A new cut takes the next free number at the end of its scene; show the effect on neighbours before changing any list.
7. **Asset change requests.** Anyone but the lead only asks: no prompt for a new asset version. List the affected cuts from the `인물·소품` column of `shot-list.md` and put request and list into handoff [5]. The lead decides; a changed fixed description becomes `_v2`, the old one goes to the discard list.
8. **Credits are one shared pool.** Quote before sending (instructions rule 10) and record in `생성/크레딧`. If `decisions.md` has a daily limit and the figures in the cut list already reach it, ask before sending.
