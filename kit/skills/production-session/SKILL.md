# 총괄 세션 + 컷 세션 운영

원칙: **기억은 문서에 두고, 세션은 쓰고 버린다.** 새 대화는 지침, 정본, 컷 카드만으로 이어서 일할 수 있어야 한다. 무엇을 읽을지는 지침의 읽기 지도가 정한다. 이 파일은 무엇을 어디에 쓰는지를 정한다.

## 1. 정본과 쓰는 사람

| 정본 | 총괄 세션 | 컷 세션 |
|---|---|---|
| `decisions.md` 확정 사항 | 고친다 | 고치지 않는다. 새 규칙은 핸드오프 [3]에 |
| `asset-registry.md` 에셋·폴더 대장 | 고친다. 확정 전 답은 그 에셋의 `초안(제안값)` 줄에, 고정 문장 칸은 확정한 뒤에 채운다 | 새 컷 폴더 ID만 |
| `shot-list.md` 컷 목록·연속성 표 | 고친다 | 자기 줄의 상태 칸과 확정 job 칸만 |
| `ok-cuts.md` OK 대장 | 승인한 세션이 그 자리에서 카드를 더하고, 같은 번호·종류의 옛 카드는 로그로 옮긴다 | (왼쪽과 같음) |
| 컷 카드 `cuts/<컷 번호>.md` | 발행. [1] [2] [8] [9]를 쓴다 | [3]~[7] [10]~[12]를 쓴다. 카드가 없으면 정본에서 초안(v0)을 만든다 |
| 로그(핸드오프, 시행착오, 옛 프롬프트) | 추가만 | 추가만 |

- 파일은 해당 줄만 고친다. 정본 문서를 통째로 다시 쓰지 않는다.
- 정본에는 지금 유효한 것만 둔다. 경위나 폐기된 것은 로그로 옮긴다. 같은 내용을 두 문서에 쓰지 않는다.
- 미디어의 정본은 Higgsfield 저장본이고, 글의 정본은 정본 문서다. 대화창은 정본이 아니다.
- 다른 세션이 고치는 중인 정본은 건드리지 않는다.
- 컷 세션 범위 밖의 문제는 고치지 않고 핸드오프 [5] "총괄에 올릴 것"에 적는다. 고정 설명문이 이 컷과 부딪치는 것(빈 장소의 "no cars"인데 버스가 나오는 컷)도 여기에 적는다.

## 2. 총괄 세션

**시작할 때:** `decisions.md`, `shot-list.md`, `asset-registry.md` 순서로 읽는다. OK 대장은 목록만 필요할 때 읽는다. 받은 핸드오프를 처리한다(§4).

**하는 일:** 구간·컷 순서·길이, 화면비·크롭·가림 구역, 시대, 그림체 기준을 정한다. 공통 에셋을 확정한다. Higgsfield 폴더 구성을 정한다. 컷 카드를 발행한다(`cut-card.md`).

**하지 않는 일:** 한 컷을 반복 생성하지 않는다. 컷 세션이 확정한 결과를 묻지 않고 바꾸지 않는다.

## 3. 컷 세션

**시작할 때 Claude가 모은다.** 사용자에게 붙여 넣기를 요구하지 않는다.
1. 컷 카드를 읽는다. 없으면 `shot-list.md`의 그 줄, `asset-registry.md`의 해당 에셋·폴더, `decisions.md`의 해당 줄로 초안을 만든다(`cut-card.md`).
2. Higgsfield 컷 폴더에서 현재 상태를 본다(`list_folders`, `list_project_assets`): 폴더 이름의 상태, `승인`·`거절` 폴더의 결과물 수, 검토 대기 중인 결과물.
3. 그 컷의 마지막 핸드오프가 있으면 읽고, [6] 다음 할 일부터 이어 간다.
4. 그 컷이 OK를 받은 적이 있으면 OK 대장에서 그 컷의 카드를 읽는다.

**하는 일:** 퍼스트 프레임 → 영상 프롬프트 → 생성 → 검수를 거쳐 사용자 확정까지 간다.

**새 대화로 넘기는 때:** 컷이 승인됐을 때, 같은 컷에서 생성·검수 왕복이 8번을 넘었을 때. 넘길 때 핸드오프(`handoff.md`)를 정본 위치의 로그에 남긴다(쓸 수 없으면 마지막 답에 출력). 다음 대화는 위 1~4로 스스로 이어받는다.

## 4. 총괄이 핸드오프를 받으면

1. job ID를 Higgsfield에서 직접 열어 확인한다. 승인 job이 OK 대장에 카드로 있는지 본다. 없으면 만든다(`higgsfield-generation` §4).
2. 확정 사항이나 에셋 대장과 충돌하는지 본다. 사용자가 확정한 요구를 약하게 만드는 변경은 받지 않고 묻는다.
3. 반영한다: `shot-list.md`(상태, 확정 job, 생성 수), `asset-registry.md`(확정본, 한계), `decisions.md`(새 규칙).
4. 이웃 컷에 영향이 있으면 그 컷들의 카드도 고친다(소품 상태, 빛, 마지막 프레임 구도).

## 5. 패킷

| 패킷 | 방향 | 틀 |
|---|---|---|
| 컷 카드 | 총괄 → 컷 | `cut-card.md` (3천 자 이하) |
| 핸드오프 | 컷 → 총괄 | `handoff.md` (40줄 이하) |

첫 줄에 받는 세션을 적는다. 한 패킷에 여러 세션 것을 섞지 않는다. 저장 폴더는 ID를 베끼지 않고 폴더 표의 행을 가리킨다.

## 6. 정본 위치별로 읽고 고치는 법

| 정본 위치 | 읽기 | 고치기 · 핸드오프 남기기 |
|---|---|---|
| Claude Doc (권장) | Docs 도구로 필요한 탭만 읽는다. OK 컷 탭과 컷 카드 탭은 제목(`3-1 영상`, `3-1`)으로 찾아 그 절만 읽는다 | 해당 줄만 고친다. OK 카드는 OK 컷 탭에, 컷 카드는 컷 카드 탭에 절로 둔다. 핸드오프는 로그 탭에 추가한다 |
| Claude 앱 프로젝트 지식 | 이미 컨텍스트에 있다. 컷 카드는 사용자가 그 컷 대화에 붙여 준 것을 쓴다 | Claude가 고칠 수 없다. "정본 갱신" 블록(파일별로 바뀐 줄만)을 출력하고, 사용자가 파일을 교체한다. OK 카드도 같은 블록으로 준다. 핸드오프는 마지막 답에 출력한다 |
| 리포 `project/` | 필요한 파일만 연다. `ok-cuts.md`는 제목으로 찾아 그 절만 연다 | 해당 줄만 고친다. 핸드오프는 `project/log/`에 쓴다 |
