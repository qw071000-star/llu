# 총괄 세션 + 컷 세션 운영

원칙: **기억은 문서에 두고, 세션은 쓰고 버린다.** 새 대화는 지침, 정본, 컷 카드만으로 이어서 일할 수 있어야 한다.

## 1. 문서 층

| 층 | 무엇 | 언제 읽나 |
|---|---|---|
| L0 | 지침 | 항상 |
| L1 | 정본 세 개 | 총괄은 매번, 컷은 카드에 옮긴 줄만 |
| L2 | 스킬 | 그 작업을 할 때 |
| L3 | 컷 카드 (3천 자 이하) | 그 컷 세션만 |
| L4 | 로그(시행착오, 옛 프롬프트) | 원인을 조사할 때만 |

**정본 규칙**
- 정본에는 지금 유효한 것만 둔다. 경위나 폐기된 것은 로그로 옮긴다.
- 미디어의 정본은 Higgsfield 저장본이고, 글의 정본은 정본 문서다. 대화창은 정본이 아니다.
- 사본을 둬야 하는 곳이 있으면, 어느 쪽이 이기는지 `decisions.md` 첫 줄에 적는다.

## 2. 총괄 세션

**시작할 때:**
1. `decisions.md`, `shot-list.md`, `asset-registry.md` 순서로 읽는다.
2. 현재 상태를 다섯 줄로 요약한다.
3. 받은 핸드오프를 처리한다(§5).

**하는 일:**
- 구간·컷 순서·길이, 화면비·크롭·가림 구역, 시대, 그림체 기준을 정한다.
- 공통 에셋을 확정한다.
- Higgsfield 폴더 구성을 정한다.
- 컷 카드를 발행한다(`cut-card.md`).

**하지 않는 일:**
- 한 컷을 반복 생성하지 않는다.
- 컷 세션이 확정한 결과를 묻지 않고 바꾸지 않는다.

## 3. 컷 세션

**시작할 때 Claude가 모은다.** 사용자에게 붙여 넣기를 요구하지 않는다.
1. 컷 카드가 정본 위치에 있으면 읽는다. 없으면 정본에서 만든다(`cut-card.md` 형식).
   - 출처: `shot-list.md`의 그 줄, `asset-registry.md`의 해당 에셋·폴더, `decisions.md`의 해당 줄
2. Higgsfield 컷 폴더에서 현재 상태를 확인한다.
   - 폴더 이름의 상태
   - `승인`·`거절` 폴더의 결과물 수
   - 검토 대기 중인 결과물
3. 그 컷의 마지막 핸드오프가 있으면 읽고, [6] 다음 할 일부터 이어 간다.

다른 컷, 전체 시나리오, 옛 시행착오는 읽지 않는다. 옛 문장이 프롬프트로 새기 때문이다.

**하는 일:** 퍼스트 프레임 → 영상 프롬프트 → 생성 → 검수를 거쳐 사용자 확정까지 간다.

**범위 밖의 문제:** 고치지 않고 핸드오프의 "총괄에 올릴 것"에 적는다.

**새 대화로 넘기는 때:**
- 컷이 승인됐을 때
- 같은 컷에서 생성·검수 왕복이 8번을 넘었을 때

넘길 때는 핸드오프를 정본 위치의 로그에 남긴다. 다음 대화는 위 1~3으로 스스로 이어받는다.

## 4. 패킷

| 패킷 | 방향 | 형식 |
|---|---|---|
| 컷 카드 | 총괄 → 컷 | `cut-card.md` (3천 자 이하) |
| 핸드오프 | 컷 → 총괄 | `handoff.md` (40줄 이하) |

- 첫 줄에 받는 세션을 적는다. 한 패킷에 여러 세션 것을 섞지 않는다.
- 고정 설명문은 에셋 대장에서 글자 그대로 복사한다.
- 저장 폴더 ID를 카드에 적는다.

## 5. 총괄이 핸드오프를 받으면

1. job ID를 Higgsfield에서 직접 열어 확인한다.
2. 확정 사항이나 에셋 대장과 충돌하는지 본다. 사용자가 확정한 요구를 약하게 만드는 변경은 받지 않고 묻는다.
3. 반영한다.
   - `shot-list.md`: 상태, 확정 job, 생성 수
   - `asset-registry.md`: 확정본, 한계
   - `decisions.md`: 새 규칙
4. 이웃 컷 카드에 영향이 있으면 그 카드도 고친다(소품 상태, 빛, 마지막 프레임 구도).

## 6. 정본 위치별로 읽고 고치는 법

| 정본 위치 | 읽기 | 고치기 · 핸드오프 남기기 |
|---|---|---|
| Claude Doc (권장) | Docs 도구로 필요한 탭만 읽는다 | 해당 줄만 고친다. 핸드오프는 로그 탭에 추가한다 |
| Claude 앱 프로젝트 지식 | 이미 컨텍스트에 있다 | Claude가 고칠 수 없다. "정본 갱신" 블록(파일별로 바뀐 줄만)을 출력하고, 사용자가 파일을 교체한다. 핸드오프는 마지막 답에 출력한다 |
| 리포 `project/` | 필요한 파일만 연다 | 해당 줄만 고친다. 핸드오프는 `project/log/`에 쓴다 |

- 다른 세션이 고치는 중인 정본은 건드리지 않는다.

## 7. 토큰을 아끼는 규칙

1. 같은 내용을 두 문서에 쓰지 않는다.
2. 프롬프트 전문은 한 번만 둔다. 대화에서는 바뀐 줄만 주고받는다.
3. 시행착오는 로그에 둔다. 정본에는 결론 한 줄과 근거 ID만 둔다.
4. 문서를 통째로 다시 쓰지 않는다.
