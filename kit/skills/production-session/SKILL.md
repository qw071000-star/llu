# 총괄 세션 + 컷 세션 운영

원칙은 하나다. **기억은 문서에 두고, 세션은 쓰고 버린다.**
새 대화는 지침, 정본 세 개, 컷 카드 한 장만 읽어도 이어서 일할 수 있어야 한다.

## 1. 문서 층

| 층 | 무엇 | 언제 읽나 | 크기 |
|---|---|---|---|
| L0 | 지침(`instructions.md`) | 항상 | 약 4천 자 |
| L1 | 정본: `decisions.md`, `asset-registry.md`, `shot-list.md` | 총괄은 매번, 컷은 카드에 옮긴 줄만 | 각 1만 자 이하 |
| L2 | 스킬 | 그 작업을 할 때 | 스킬당 1만 자 이하 |
| L3 | 컷 카드 | 그 컷 세션만 | 3천 자 이하 |
| L4 | 로그(시행착오, 옛 프롬프트, 측정값) | 원인을 조사할 때만 | 제한 없음 |

**정본에는 지금 유효한 것만 둔다.**
- 경위나 폐기된 프롬프트는 로그로 옮긴다.
- 한 문서에 개정 이력 266번이 쌓였을 때 세션마다 그 이력을 읽느라 토큰이 샜고, 옛 결정과 새 결정이 섞였다.

**정본은 하나다.**
- 미디어는 Higgsfield 저장본이 정본이다.
- 글은 정본 문서가 정본이다. 대화창은 정본이 아니다.
- 사본을 둬야 하는 곳(콘티 사이트, JSON)이 있으면, 어느 쪽이 이기는지 `decisions.md` 첫 줄에 적는다.

## 2. 총괄 세션

**시작할 때**
1. `decisions.md`, `shot-list.md`, `asset-registry.md` 순서로 읽는다.
2. 현재 상태를 다섯 줄로 요약한다.
3. 받은 핸드오프를 처리한다(§5).

**하는 일**
- 구간·컷 순서·길이, 화면비·크롭·가림 구역, 시대, 그림체 기준을 정한다.
- 공통 에셋(인물 시트, 장소 마스터, 그림체 기준)을 확정한다.
- Higgsfield 폴더 구성을 정하거나 확인한다(`higgsfield-generation` 스킬).
- 컷 카드를 발행한다(`cut-card.md` 형식).

**하지 않는 일**
- 한 컷을 반복 생성하지 않는다.
- 컷 세션이 확정한 결과를 묻지 않고 바꾸지 않는다.

## 3. 컷 세션

**입력:** 컷 카드 한 장.
- 다른 컷, 전체 시나리오, 옛 시행착오는 읽지 않는다.
- 옛 문장이 프롬프트로 새는 것을 막기 위해서다.

**하는 일:** 퍼스트 프레임 이미지, 영상 프롬프트, 생성, 검수를 거쳐 사용자 확정까지 간다.

**범위 밖의 문제를 발견하면:** 고치지 않고 핸드오프의 "총괄에 올릴 것"에 적는다.
- 예: 장소 마스터가 틀렸다, 이웃 컷과 구도가 겹친다.

**새 대화로 넘기는 때:**
- 컷이 승인됐을 때.
- 같은 컷에서 생성·검수 왕복이 8번을 넘었을 때.
- 앞의 결정을 다시 확인해야 할 만큼 대화가 길어졌을 때.

넘길 때는 핸드오프를 쓴다. 새 대화는 컷 카드와 마지막 핸드오프만 받고 시작한다.

## 4. 패킷 — 세션 사이에 오가는 것은 두 가지뿐

| 패킷 | 방향 | 형식 | 길이 |
|---|---|---|---|
| 컷 카드 | 총괄 → 컷 | `cut-card.md` | 3천 자 이하 |
| 핸드오프 | 컷 → 총괄 | `handoff.md` | 40줄 이하 |

- 첫 줄에 받는 세션을 적는다(`받는 세션: 총괄`, `받는 세션: C07`). 한 패킷에 여러 세션 것을 섞지 않는다.
- 컷 카드의 고정 설명문(인물, 의상, 장소)은 에셋 대장에서 글자 그대로 복사한다.
- 컷 카드에는 저장 폴더 ID를 적는다. 그래야 컷 세션이 저장 위치를 다시 묻지 않는다.

## 5. 총괄이 핸드오프를 받으면

1. job ID를 Higgsfield에서 직접 열어 확인한다. 보고만 믿지 않는다.
2. 확정 사항이나 에셋 대장과 충돌하는지 본다. 사용자가 확정한 요구를 약하게 만드는 변경은 받지 않고 사용자에게 묻는다.
3. 반영한다.
   - `shot-list.md`: 상태, 확정 job, 누적 생성 수
   - `asset-registry.md`: 확정본, 한계
   - `decisions.md`: 새 규칙
4. 이웃 컷 카드에 영향이 있으면(소품 상태, 빛, 마지막 프레임 구도) 그 카드도 고친다.

## 6. 정본을 고치는 방법 (환경별)

- **Claude 앱 프로젝트:** Claude는 지식 파일을 직접 고칠 수 없다.
  - 총괄 세션 끝에 "정본 갱신" 블록을 출력한다. 파일별로 바뀐 줄만 넣는다.
  - 사용자는 그 블록으로 지식 파일을 교체한다.
  - Docs 커넥터를 쓰면 정본을 Doc으로 두고 해당 줄만 고친다.
- **Claude Code(리포):** `project/` 아래 파일에서 해당 줄만 고친다. 다른 세션이 고치는 중인 파일은 건드리지 않는다.

## 7. 토큰을 아끼는 규칙

1. 같은 내용을 두 문서에 쓰지 않는다. 한쪽만 고쳐지면 모순이 생긴다.
2. 프롬프트 전문은 한 번만 둔다. 대화에서는 바뀐 줄만 주고받는다.
3. 컷 세션에 전체 시나리오나 모든 컷 표를 넣지 않는다.
4. 시행착오는 로그에 둔다. 정본에는 결론 한 줄과 근거 ID만 둔다.
5. 문서를 통째로 다시 쓰지 않는다. 해당 줄만 고친다.
6. 대화가 길어지면 요약해서 계속하지 말고 핸드오프를 쓴 뒤 새 대화로 넘긴다. 긴 대화일수록 앞의 결정을 잊고 같은 실수를 되풀이한다.
