# 영상 프롬프트 — 공통

근거:
- 「어머니와 고등어」 씬 1 (Seedance 2.5로 약 100회)
- The Prompter 씬 1 (영상 66개 분석)
- 나부코 배경 (Kling 4.0으로 76회)

## 읽을 파일 — 이 파일 + 해당하는 것만

| 할 일 | 파일 |
|---|---|
| 인물·소품·대사가 있는 실사 컷을 새로 쓴다 | `live-action.md` (+ 연기는 `acting` 스킬) |
| 인물 연기가 없는 배경·풍경·그림체 영상을 새로 쓴다 | `background.md` |
| 결과가 틀려서 고친다 | `fixes.md`에서 그 증상 줄만 |
| 확정한 저해상도 테이크를 고해상도로 다시 렌더한다 | `rerender.md` |

**고칠 때는 형식 파일과 빈 틀을 다시 읽지 않는다.**
1. 확정 프롬프트를 가져온다. Higgsfield에서는 `get_project_asset_prompt`로 그 job의 프롬프트를 받는다.
2. `fixes.md`에서 해당 증상을 찾는다.
3. 바뀐 줄만 "전 → 후"로 보인다. 한 번에 한 가지만 바꾼다.
4. 전문은 사용자가 직접 붙여 넣어야 할 때만 보인다.

## 1. 먼저 기억할 일곱 줄

1. **사건 수가 성패를 가른다.** 글자 수보다 한 생성에 넣는 사건 수가 중요하다. 풀린 판은 대개 컷·동작·요소·대사 수를 줄인 판이었다.
2. **전환이 아니라 상태를 쓴다.** "점점 무너진다" 대신 시작 상태와 끝 상태를 고정한다. 그 사이가 길면 생성을 나눈다.
3. **첫 프레임은 영상의 0:00이다.** 시작 이미지가 0:00이고, 프롬프트의 첫 프레임 문단도 그 이미지와 같아야 한다.
4. **카메라 동작은 한 생성에 하나.** 고정 + 궤도, 달리 + 줌처럼 겹치지 않는다.
5. **좌우는 화면 기준으로 정하고, 본문에서는 화면 속 물건으로 가리킨다.** "화면 오른쪽 손"은 네 번 연속 인물 자신의 오른손으로 읽혔다. "신발장 쪽 손"처럼 쓴다.
6. **참조마다 통제 범위를 적는다.** 장소 참조는 카메라·구도를 통제하지 않는다. 인물 참조는 얼굴·의상만 통제한다.
7. **위험마다 막는 문장 한 줄.** 쓰기 전에 실패 위험을 꼽고 하나씩 막는다. 금지 목록을 끝없이 늘리지 않는다.

## 2. 샷 설계 — 프롬프트를 쓰기 전에

| 정할 것 | 기준 |
|---|---|
| 길이 | 대사·동작이 있는 실사 5~10초, 배경 10~15초. 15초를 넘으면 둘로 나눈다. 끝 프레임을 넣은 30초 영상은 속도가 5배로 몰리고 그림체가 무너졌다 |
| 이어 붙이기 | 뒤 생성은 앞 생성의 지정 프레임을 `start_image`로 받는다. Extend는 꼭 필요할 때만 쓴다 |
| 장소 | 한 생성에 한 장소. 새 장소는 먼저 이미지로 확정한다. 한 클립에서 장소가 세 번 바뀌자 모델이 빈 곳을 엉뚱한 건물로 채웠다 |
| 사건 수 | 한 생성에 1~3개. 인물마다 할 일은 하나. 대사는 한 줄에 2~4초 |
| 끝 프레임 | 꼭 도착해야 할 구도가 있을 때만 쓴다. 없으면 다음 컷 첫 프레임을 말로 설계해 컷으로 잇는다 |

**반복 실패의 신호:** 같은 핵심 실패가 연속 2회, 또는 최근 4회 중 3회 나오면 문장을 더하지 않는다. 샷을 바꾼다(컷 삭제, 동작 삭제, 요소 삭제, 둘로 나누기, 개념 단순화).

## 3. 모델 메모 (관찰한 것)

| 모델 | 메모 |
|---|---|
| Seedance 2.5 | 참조 요소를 `<<<요소ID>>>`로 부른다. 붙인 요소와 프롬프트 속 요소를 정확히 맞춘다. 소리가 기본으로 켜져 있어 AUDIO 블록이 필요하다. 음성 참조는 붙인 순서대로 audio_1, audio_2다. Extend 결과는 원본이 21:9여도 16:9 1280×720이었다 |
| Kling 4.0 | 이미지를 영상으로 만든다(3~30초). 이미지에 있는 것을 다시 쓰지 않고 움직임과 유지할 것만 쓴다. 카메라는 별도 문단으로 쓰고 끝 상태는 쓰지 않는다 |
| 공통 한계 | 다음은 거의 지켜지지 않았다. 2회 시도한 뒤 후반 작업으로 넘긴다.<br>• 정확한 이동 거리<br>• 정확한 등장·퇴장 타이밍<br>• 작고 어두운 풀의 흔들림<br>• 별 반짝임<br>• 칠해진 빛줄기의 회전 |

## 4. 보내기 전 점검

- [ ] 사건이 3개 이하인가, 15초 이하인가
- [ ] 첫 프레임 문단이 시작 이미지(0:00)와 같은가
- [ ] 좌표 문장이 있고, 본문의 좌우를 화면 속 물건으로 썼는가
- [ ] 붙인 참조와 프롬프트 속 참조가 정확히 일치하고, 각각 권한을 적었는가. 장소 참조에 구도 권한을 주지 않았는가
- [ ] 카메라 동작이 하나인가, 렌즈는 화각(도) + 관찰 결과 3개인가
- [ ] 횟수(한 번 / 정확히 두 번 / 계속)와 범위(첫 프레임 / 구간 / 전체 / 마지막)가 그대로인가
- [ ] 인물·장소 설명문이 에셋 대장과 글자까지 같은가. 이 샷에 없는 인물이나 옛 문장이 남아 있지 않은가
- [ ] 위험마다 막는 문장이 한 줄씩 있는가
- [ ] 해상도와 길이가 확인용인가. 저장 폴더가 정해졌는가
