# 영상 프롬프트 — 공통

## 읽을 파일 — 이 파일 + 해당하는 것만

| 할 일 | 파일 |
|---|---|
| 인물·소품·대사가 있는 실사 컷 | `live-action.md` (+ 연기는 `acting` 스킬) |
| 인물 연기가 없는 배경·풍경·그림체 | `background.md` |
| 결과가 틀려서 고친다 | `fixes.md`에서 그 증상 줄만 |
| 확정한 저해상도 테이크를 고해상도로 | `rerender.md` |

**고칠 때:** 형식 파일과 빈 틀을 다시 읽지 않는다.
1. 확정 프롬프트를 그 job에서 가져온다(`get_project_asset_prompt`).
2. `fixes.md`에서 해당 증상을 찾는다.
3. 바뀐 줄만 "전 → 후"로 보인다.

## 1. 일곱 원칙

1. **사건 수가 성패를 가른다.** 글자 수보다 중요하다. 안 풀리면 컷·동작·요소·대사를 줄인다.
2. **전환이 아니라 상태를 쓴다.** 시작 상태와 끝 상태를 고정한다. 사이가 길면 생성을 나눈다.
3. **첫 프레임은 영상의 0:00이다.** 첫 프레임 문단은 시작 이미지와 같아야 한다.
4. **카메라 동작은 한 생성에 하나.**
5. **좌우는 화면 기준이다.** 본문에서는 화면 속 물건으로 가리킨다(`the hand nearer the [object]`). "오른손"은 인물 기준으로 읽힌다.
6. **참조마다 통제 범위를 적는다.** 장소 참조는 구도를 통제하지 않고, 인물 참조는 얼굴·의상만 통제한다.
7. **위험마다 막는 문장 한 줄.** 금지 목록을 늘리지 않는다.

## 2. 샷 설계

| 정할 것 | 기준 |
|---|---|
| 길이 | 대사·동작 실사 5~10초, 배경 10~15초. 15초를 넘으면 나눈다 |
| 이어 붙이기 | 뒤 생성은 앞 생성의 지정 프레임을 `start_image`로 받는다 |
| 장소 | 한 생성에 한 장소. 새 장소는 먼저 이미지로 확정한다 |
| 사건 수 | 한 생성에 1~3개. 인물마다 할 일 하나. 대사 한 줄에 2~4초 |
| 끝 프레임 | 꼭 도착해야 할 구도가 있을 때만 쓴다 |

## 3. 모델 메모

| 모델 | 메모 |
|---|---|
| Seedance 2.5 | 참조는 `<<<요소ID>>>`로 부르고, 붙인 요소와 정확히 맞춘다. 소리가 기본으로 켜져 있어 AUDIO 블록이 필요하다. 음성 참조는 붙인 순서대로 audio_1, audio_2다. Extend는 화면비가 바뀔 수 있다 |
| Kling 4.0 | 이미지에 있는 것을 다시 쓰지 않고 움직임과 유지할 것만 쓴다. 카메라는 별도 문단으로 쓰고, 끝 상태는 쓰지 않는다 |

## 4. 보내기 전 점검 (검사 스크립트가 잡지 못하는 것)

- [ ] 첫 프레임 문단이 시작 이미지(0:00)와 같은가
- [ ] 참조마다 권한을 적었는가. 장소 참조에 구도 권한을 주지 않았는가
- [ ] 렌즈를 화각(도) + 관찰 결과 3개로 썼는가
- [ ] 횟수(한 번 / 계속)와 범위(첫 프레임 / 구간 / 전체)를 지켰는가
- [ ] 이 샷에 없는 인물이 남아 있지 않은가
- [ ] 위험마다 막는 문장이 있는가
