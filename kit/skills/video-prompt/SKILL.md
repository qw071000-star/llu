# 영상 프롬프트 — 공통

## 읽을 파일 — 이 파일 + 해당하는 것만

| 할 일 | 파일 |
|---|---|
| 인물·소품·대사가 있는 실사 컷 | `live-action.md` (+ 연기는 `acting` 스킬) |
| 인물 연기가 없는 배경·풍경·그림체 | `background.md` |
| 결과가 틀려서 고친다 | `fixes.md`에서 그 증상 줄만 |
| 확정한 저해상도 테이크를 고해상도로 | `rerender.md` |
| 다른 OK를 기준으로 ("3-1의 모션처럼") | `production-session` → `ok-reuse.md` |

**고칠 때:** 형식 파일과 빈 틀을 다시 읽지 않는다.
1. 확정 프롬프트를 OK 대장 카드에서 가져온다. 카드가 없으면 그 job에서 가져온다(`get_project_asset_prompt`).
2. `fixes.md`에서 해당 증상을 찾는다.
3. 바뀐 줄만 "전 → 후"로 보인다.

## 0. 쓰기 전 정보 점검

**프롬프트를 쓰기 전에 아래 표를 모두 채운다.** 표의 각 줄은 15블록의 한 블록에 들어간다. 빈 칸이 있으면 프롬프트를 쓰지 않는다.

| 구분 | 필요한 정보 | 들어가는 블록 |
|---|---|---|
| 장면 | 이 클립에서 일어나는 일(2~4문장), 시대·장소·시간대 | `SCENE_CONTEXT` |
| 형식 | 길이, 화면비, 모델, 소리(대사·효과음·음악 여부), 저장 폴더 | `FORMAT_MODE`, `AUDIO` |
| 룩 | 매체·질감·색조(`decisions.md`의 룩 기준) | `STYLE` |
| 인물 에셋 | 인물마다 요소 ID, 의상·헤어 상태 버전, 고정 설명문, 대사가 있으면 목소리 문장 | `ACTIVE_REFERENCES`, `AUDIO` |
| 장소 | 장소 뷰 요소 ID, 화면 좌·중·우·전경의 랜드마크, 시간대 | `ACTIVE_REFERENCES`, `LOCATION_MAP` |
| 소품 | 요소 ID, 시작 상태 → 끝 상태, 누가 어느 손(물건 기준)에 드는가, 크기 | `ACTIVE_REFERENCES`, `PHYSICS` |
| 시작 이미지 | 퍼스트 프레임 job (없으면 퍼스트 프레임부터 만들자고 묻는다), 끝 프레임을 쓸지 | `ACTIVE_REFERENCES` |
| 카메라 | 위치(물건 기준), 높이, 방향, 고정 또는 움직임 한 가지(종류·속도·양) | `CAMERA` |
| 렌즈 | 대각 화각(도), 관찰 결과 3개, 심도·초점 이동 | `OPTICS` |
| 인물 위치 | 인물마다 시작 위치(0:00, 물건 기준)·자세·하던 동작, 끝 위치(마지막 프레임) | `FIRST_FRAME_AND_SPATIAL_BLOCKING`, `ACTION_TIMING` |
| 동선 | 이동 경로, 지나가지 않는 구역, 걸음 속도 | `LOCATION_MAP`, `ACTION_TIMING` |
| 시선 | 인물마다 무엇을 보는지, 언제 시선이 바뀌는지, 반응하지 않을 사람 | `ACTION_TIMING`, `CHARACTER_ACTING` |
| 타이밍 | 주요 액션의 구간(`0:00–0:03`), 대사 원문·횟수·위치, 소품 상태가 바뀌는 시점 | `ACTION_TIMING`, `AUDIO` |
| 연기 | 인물마다 목표, 감정 범위의 양 끝 | `CHARACTER_ACTING` |
| 빛 | 지배 광원과 방향 | `LIGHTING` |
| 이음새 | 앞 컷에서 이어받는 상태, 다음 컷 첫 프레임과 맞출 것 | `PRE_SHOT_CONTINUITY` |
| 금지 | 이 컷과, 가져온 OK에서 실제로 났던 실패(OK 카드의 "위험 → 막는 문장", 에셋 대장의 인물 "알려진 실패") | `REQUIRED_AND_FORBIDDEN_CONSTRAINTS` |

배경·풍경 영상(4문단)이면 다음 표만 채운다.

| 필요한 정보 | 들어가는 문단 |
|---|---|
| 시작 이미지 job, 모델, 길이, 화면비, 저장 폴더 | 설정 |
| 카메라 움직임: 종류·방향·양(화면 %)·속도 | `Camera` |
| 움직일 것: 이미지에 이미 있는 것마다 방향·속도 | `Motion` |
| 매체, 유지할 형태, 빛 방향 | `Keep` |
| 소리(끌 수 있는지) | `Silent` |

**채우는 순서**
1. 사용자 메시지
2. 컷 카드
3. 정본(`shot-list.md`, `decisions.md`, `asset-registry.md`)
4. OK 대장(이 컷의 OK, 사용자가 기준으로 말한 OK)
5. Higgsfield(확정 이미지)
6. 이웃 컷의 끝 상태

**그래도 빈 칸이면 추측하지 않고 한 번에 묻는다.**
- 사용자가 말하지 않은 칸도 표에 있으면 묻는다. 사용자는 렌즈, 시선, 타이밍을 먼저 말하지 않는 경우가 많다.
- 질문마다 제안값과 그 이유를 붙인다.
- `decisions.md`에 기본값이 있는 칸(길이, 카메라 기본, 해상도, 소리)은 묻지 않는다. 한 줄로만 보인다: `기본값으로 씀: 8초 · 고정 카메라 · 480p · 효과음만`.
- 질문이 10개를 넘으면 묶음(카메라 / 인물 / 타이밍)으로 나누고 묶음마다 제안을 한 줄로 낸다.

```
프롬프트를 쓰기 전에 확인할 것이 [N]개 있습니다. 제안값이 괜찮으면 "그대로"라고 해 주세요.
[카메라]
1. 위치·높이: 제안 — [물건] 맞은편, 눈높이 (이유: 앞 컷과 같은 축)
2. 렌즈: 제안 — 대각 약 [N]° (이유: [무엇]이 한 화면에 다 들어옴)
[인물]
3. [인물 A] 시작 → 끝 위치: 제안 — [물건] 옆에서 [물건] 쪽으로 [N]걸음 (이유: 다음 컷 첫 프레임 위치)
4. [인물 A] 시선: 제안 — 0:00–0:03 [대상], 이후 [대상] (이유: [무엇]에 반응)
[타이밍]
5. 주요 액션: 제안 — 0:03에 [동작], 0:05에 대사 한 번 (이유: 사건 3개 이하)
```

**답이 일부만 오면** 남은 것만 다시 묻는다. "그대로", "알아서", "몰라", "아무거나"면 제안값을 쓰고 컷 카드에 `제안값`이라고 적는다.

**답 하나 때문에 다른 제안값이 맞지 않게 되면** 바뀐 제안을 보이고 확인받는다. 혼자 바꾸지 않는다.

**답을 받은 뒤**
1. 컷 카드 [4]~[6]에 기록한다.
2. 프롬프트는 컷 카드의 값과 에셋 대장의 고정 설명문을 글자 그대로 옮겨 쓴다.
3. 다시 시도하거나 다음 컷을 쓸 때도 같은 값을 쓴다. 값이 바뀌면 컷 카드를 먼저 고친다.

**일관성 점검 (쓰고 나서)**
- 이 컷의 시작 상태가 앞 컷의 끝 상태와 같은가(위치, 소품 상태, 빛)
- 같은 장소의 다른 컷과 좌우 기준, 광원 방향, 렌즈 계열이 맞는가
- 인물·의상·장소 설명문이 에셋 대장과 글자까지 같은가

## 1. 일곱 원칙

1. **사건 수가 성패를 가른다.** 글자 수보다 중요하다. 안 풀리면 컷·동작·요소·대사를 줄인다.
2. **전환이 아니라 상태를 쓴다.** 시작 상태와 끝 상태를 고정한다. 사이가 길면 생성을 나눈다.
3. **첫 프레임은 영상의 0:00이다.** 첫 프레임 문단은 시작 이미지와 같아야 한다.
4. **카메라 동작은 한 생성에 하나.**
5. **좌우는 화면 기준이다.** 본문에서는 화면 속 물건으로 가리킨다(`the hand nearer the [object]`). "오른손"은 인물 기준으로 읽힌다.
6. **참조마다 통제 범위를 적는다.** 장소 참조는 구도를 통제하지 않고, 인물 참조는 얼굴·의상만 통제한다.
7. **위험마다 막는 문장 한 줄.** 금지 목록을 늘리지 않는다.

## 2. 샷 설계

| 정할 것 | 기준 |
|---|---|
| 길이 | 정본의 컷 길이를 따른다. 정본에 없으면 대사·동작 실사 5~10초, 배경 10~15초. 15초를 넘으면 나눈다 |
| 렌즈 환산 | 대각 화각은 풀프레임 기준으로 환산한다: 24mm 84° · 28mm 75° · 35mm 63° · 50mm 47° · 75mm 32° · 85mm 29° · 100mm 24° · 135mm 18°. 컷 카드와 시작 이미지가 다르면 시작 이미지가 이긴다. 다르다는 것을 사용자에게 알린다 |
| 이어 붙이기 | 뒤 생성은 앞 생성의 지정 프레임을 `start_image`로 받는다 |
| 장소 | 한 생성에 한 장소. 새 장소는 먼저 이미지로 확정한다 |
| 사건 수 | 한 생성에 1~3개. 인물마다 할 일 하나. 대사 한 줄에 2~4초 |
| 끝 프레임 | 꼭 도착해야 할 구도가 있을 때만 쓴다 |

## 3. 모델 메모

| 모델 | 메모 |
|---|---|
| Seedance 2.5 | 참조는 `<<<요소ID>>>`로 부르고, 붙인 요소와 정확히 맞춘다. 소리가 기본으로 켜져 있어 AUDIO 블록이 필요하다. 음성 참조는 붙인 순서대로 audio_1, audio_2다. Extend는 화면비가 바뀔 수 있다 |
| Kling 4.0 | 이미지에 있는 것을 다시 쓰지 않고 움직임과 유지할 것만 쓴다. 카메라는 별도 문단으로 쓰고, 끝 상태는 쓰지 않는다 |

## 4. 보내기 전 점검 (검사 스크립트가 잡지 못하는 것)

- [ ] 첫 프레임 문단이 시작 이미지(0:00)와 같은가
- [ ] 참조마다 권한을 적었는가. 장소 참조에 구도 권한을 주지 않았는가
- [ ] 렌즈를 화각(도) + 관찰 결과 3개로 썼는가
- [ ] 횟수(한 번 / 계속)와 범위(첫 프레임 / 구간 / 전체)를 지켰는가
- [ ] 이 샷에 없는 인물이 남아 있지 않은가
- [ ] 위험마다 막는 문장이 있는가. 같은 증상을 막는 문장이 이미 있으면 더하지 않고 그 문장을 바꿨는가
- [ ] 가져온 OK가 있으면, 그 OK의 Required·Forbidden 중 가져온 동작·인물에 걸린 줄도 옮겼는가
- [ ] 보이기 전에 검사 스크립트를 돌렸는가(`higgsfield-generation` §1의 5번). 코드 실행이 안 되면 그렇다고 적는다
