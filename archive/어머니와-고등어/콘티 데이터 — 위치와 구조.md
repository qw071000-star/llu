## 2. 콘티 한 컷은 네 군데에 나뉘어 있다
 
| 무엇 | 어디 | 키 |
|---|---|---|
| **콘티 텍스트 원본** | Main HTML 안의 `var SC = [...]` | 씬 `no, tense, slug, intent, cast, props, look, chronology, cuts[]` / 컷 `n, displayLabel, size, lens, angle, move, sec, desc, note, cameraKo, lines` |
| **콘티 텍스트 덮어쓰기** (있으면 우선) | `embeddedTextOverrides.json` **그리고** `embeddedCharacterData.json`의 `textOverrides` | `cut:N:desc` `note` `camera` `size` `lens` `move` `angle` `duration` `line:K` / `scene:N:slug` `look` `cast` `intent` `sound` `props` `space-note` / `place:<id>:title` … |
| **이미지 프롬프트** (컷의 첫 프레임) | `embeddedCharacterData.json`의 `promptBodies` | `image:N` (N = C# 번호) · 장소 기준판은 `place:<id>` |
| **영상 프롬프트** | 같은 `promptBodies` | `video:C#N` |
| 에셋 배정 | `embeddedAssetData.json` | 프레임 `image:N` / 영상 `video:C#N` / 컷 `cutAssignments["N"]` |
| 인물·의상 배정, 진행 상태 | `embeddedCharacterData.json` | `cutCast`, `cutOutfits`, `sceneCast`, `sceneOutfits`, `cutStatus`(`imageDone`/`videoDone`), `assetStatus` |
 
- 화면은 **덮어쓰기 → 원본** 순서로 읽는다. 콘티 텍스트를 고칠 때는 HTML의 `SC`(앱 코드)를 건드리지 말고 덮어쓰기 키를 넣는다.
- 덮어쓰기 두 벌은 글자까지 같고, **항상 같이** 고친다. 사이트는 열 때 `embeddedTextOverrides.json`을 읽고, 저장할 때 두 파일을 함께 쓴다.
- `embeddedPromptOverrides.json`은 비어 있는 옛 자리다. 프롬프트는 `promptBodies`에 있다.
- 컷 번호(C#)는 결번이 있다. 씬 1은 C#7이 없고(9컷), C#8의 표시 라벨은 `1-7`이다. **키는 전부 C# 번호다. 표시 라벨과 섞지 않는다.**
**현재 프롬프트 형식** (바꾸기 전에 사용자에게 확인한다 — `film-decisions.md` 미결 #5·#6)
- `image:N`은 전부 **한국어 `【형식】【카메라·구도】【한순간】【빛】…` 블록**이다.
- `video:C#N`은 두 형식이 섞여 있다. C#1~C#47 등은 **15단계**(`[SCENE_CONTEXT]` … `[REQUIRED_AND_FORBIDDEN_CONSTRAINTS]`, 한국어 본문), 나머지는 옛 `【형식】` 블록이다.
- 콘티에 없는 연출을 보탠 문장에는 `〔보완: 콘티 미지정 — 뺄 수 있음〕` 표시가 붙어 있다. 새로 보탤 때도 같은 표시를 쓴다.
읽는 법 (예시):
 
```python
d='pages/어머니와_고등어_Main_V3.1.data/'
h=open('pages/어머니와_고등어_Main_V3.1.html',encoding='utf-8').read()
i=h.find('var SC = ')+len('var SC = ')
SC,_=json.JSONDecoder().raw_decode(h[i:])
ov=json.load(open(d+'embeddedTextOverrides.json'))
cd=json.load(open(d+'embeddedCharacterData.json'))
desc  = ov.get(f'cut:{n}:desc', cut['desc'])
img   = cd['promptBodies'].get(f'image:{n}')
video = cd['promptBodies'].get(f'video:C#{n}')
```
 
### 2.1 콘티를 고칠 때 같이 보는 곳 — 컷 하나 기준
 
1. **텍스트**: `cut:N:*` 덮어쓰기 (두 벌 모두)
2. **이미지 프롬프트** `image:N`: 바뀐 카메라·한순간·소품 상태가 반영됐는가. 이미지는 영상 0:00 상태다
3. **영상 프롬프트** `video:C#N`: 타임라인·대사·카메라·필수/금지 조건이 새 텍스트와 맞는가
4. **배정**: 뷰(`LC-…-Vn`)·인물·의상·소품이 바뀌면 `embeddedAssetData.json`의 `image:N`·`video:C#N`, `cutCast`·`cutOutfits`
5. **짝 컷**: C#9↔C#110, C#10↔C#109처럼 같은 자리·같은 얼굴로 묶인 컷, 그리고 앞뒤 컷의 연속성(봉지 상태표 등)
6. 고칠 게 없는 칸은 건드리지 않는다. 한 칸만 바꿔 달라는 요청이면 나머지는 **어긋난 곳을 보고만** 하고 사용자에게 묻는다
씬 단위 변경(`scene:N:*`)이면 그 씬의 모든 컷 프롬프트에서 같은 문장(시대 잠금, 고정 요소)을 확인한다.
 
## 3. `embeddedAssetData.json` 구조
 
```
version, revision                 ← revision은 저장할 때마다 서버가 올린다(캐릭터 데이터도). 임의로 건드리지 않는다
assets                            { "LC-002": {...}, ... }
assignments                       "image:N" → [에셋ID]   프레임 이미지 단위. 여기서는 뷰(LC-002-V2)까지 배정된다
cutAssignments                    "N"       → [에셋ID]   컷 단위. 장소는 부모(LC-002)로만 배정된다
sceneAssignments                  "1".."10" → [에셋ID]
catalogLinks                      카탈로그 키 → [에셋ID]
scenePlan                         씬 계획 + 번호 규칙(numberingNote)
scene14PromptKeys                 영상 프롬프트 키 목록 ("video:C#N")
```
 
에셋 한 건의 필드: `id, type, tag, name, description, image, parentId, scenes, status, source, catalogIds`.
 
```json
{
  "id": "LC-002-V3",
  "type": "locations",
  "tag": "@loc_yh_home_current_v3",
  "name": "현재 집 — 주방→거실(리버스)",
  "description": "… v2의 반대축. job_id c9ca0cad, 검수 통과.",
  "image": "https://d8j0ntlcm91z4.cloudfront.net/.../hf_…_c9ca0cad-….png",
  "parentId": "LC-002",
  "scenes": [1, 10],
  "status": "★확정"
}
```
 
(필드 형식 예시다. 이 V3 주소는 이미 열리지 않았다 — `film-decisions.md` §8.)
 
- `image`는 **문자열 하나**(URL)다. 배열이 아니다.
- `status`는 `★확정` / `검수 대기` / 비어 있음.
- **job_id 전용 필드는 없다.** 확정 이미지의 job_id는 `image` URL 파일명 끝의 UUID와 같고, `description` 끝에 `job_id xxxxxxxx`로 앞 8자리를 적는다(V3·V6이 이미 이 방식). 부모 job·폐기 job처럼 JSON이 담지 못하는 이력은 `location-assets.md`에 적는다.
- 씬 번호는 `scenes`에 **데이터 번호(1~10)**로 들어간다.
## 4. 뷰는 `parentId`로 구현돼 있다
 
```
LC-002       @loc_yh_home_current              image: null   ← 부모. 장소 정체성(설명문)만
LC-002-V1    @loc_yh_home_current_v1           현관
LC-002-V2    @loc_yh_home_current_v2           거실→주방 (기본 축)
LC-002-V3    @loc_yh_home_current_v3           주방→거실 (리버스)
LC-002-V4    @loc_yh_home_current_table_hi     식탁 상판 직부감
LC-002-V5    @loc_yh_home_current_counter      조리대 근접
LC-002-V6    @loc_yh_home_current_v6           스탠드 옆→식탁·현관 통로 (C#3)
```
 
`image`가 하나뿐이라 **뷰 하나 = 에셋 한 건**이고, 부모–자식은 `parentId`로 묶인다.
태그 규칙이 V1~V3·V6(`_vN`)과 V4·V5(`_table_hi`, `_counter`)로 섞여 있다. 태그는 Higgsfield 요소 이름과 같아야 하므로 **바꾸지 말고 있는 그대로 부른다.**
 
**새 뷰를 추가하는 법**: `assets`에 `LC-002-V7` 항목을 추가하고
`parentId: "LC-002"`, `tag`, `image`(결과 URL), `description`(끝에 `job_id xxxxxxxx`), `status`를 넣는다.
그 뷰를 쓰는 프레임을 `assignments`의 `image:N`에 더한다.

## 6. 작업 방식
 
- 읽기·검색은 `device_bash` + `python3`로 JSON을 직접 다룬다. 큰 파일은 통째로 출력하지 않는다.
- JSON 속 `<`는 R2에서 `\u003c`로 저장돼 내려온다. 문자열 검색은 파싱한 뒤에 한다.
**고칠 때는 반드시 이 순서**:
 
0. 사용자에게 **사이트 탭(conti·conti-beta 모두)을 닫았는지** 확인한다. 열린 탭이 자동저장하면 `embeddedCharacterData`·`embeddedTextOverrides`를 파일째 덮는다.
1. `cd ~/Documents/LucianWork_Page && node worker/scripts/pull-r2.mjs`
2. 고칠 파일을 `pages/archive/<파일명>.<YYYYMMDD-HHMMSS>.bak`으로 복사한다.
3. **읽기–수정–쓰기 스크립트**로 고친다. 파일 내용을 다시 타이핑하지 않는다. 저장 뒤 `python3 -m json.tool`로 검사한다.
4. `node worker/scripts/push-r2.mjs <고친 파일 경로>` — 고친 파일만 올린다. `--all`은 쓰지 않는다.
   콘티 텍스트·프롬프트를 고쳤으면 보통 `embeddedTextOverrides.json` + `embeddedCharacterData.json` 두 개, 배정까지 바꿨으면 `embeddedAssetData.json`도.
5. 사용자에게 사이트 탭을 새로 열어 확인해 달라고 한다.
- 1→4는 짧게 끝낸다. **충돌 감지가 없다** — 그 사이 사이트에서 같은 파일이 저장되면 push가 덮고, 1분 주기 자동 동기화는 맥의 미반영 수정을 덮는다. 서로 다른 파일이면 문제없다.
- 사이트에서 편집할 때도 **탭은 하나만** 연다. 두 탭(또는 두 기기)에서 같은 문서를 열어 두면 늦게 저장한 탭이 먼저 저장한 내용을 덮는다.
- pull·push 대상은 `pages/*.html`, `pages/*.data/*.json`, `frames/`, `uploads/`뿐이고, 이름이 `.`으로 시작하는 파일은 올라가지 않는다. 삭제·이름 변경은 동기화되지 않는다. 파일을 지우거나 옮기지 않는다.
- `conti-beta.lucianwork.com`은 같은 데이터다. 테스트용으로 쓰지 않는다.
- 되돌리기: 덮어써진 판은 GitHub `lucianwork-conti` 커밋 이력에서 파일을 복원해 push한다(맥이 켜져 1분 주기 커밋이 돈 판만 남는다). 사이트 자체가 이상하면 `worker/scripts/cutover.sh --rollback`(예전 맥 서버로 돌린다). 자세한 대처는 맥 문서 「문제가 생겼을 때」.
