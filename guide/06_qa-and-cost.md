## 1. 생성 파이프라인 — 싸게 확인하고 비싸게 확정한다

```
① 컷 설계(사건·길이·카메라·첫 프레임)  → 사용자 확인
② 위험 목록 + 프롬프트 전문            → 사용자 확인 (생성 지시가 있어야 다음)
③ 확인용 생성 1회: 이미지 1k / 영상 480p·짧게
④ 검수 보고(눈 + 숫자)                   → 사용자 판단
⑤ 고칠 것 하나만 바꿔 1회 더 (최대 2회)  → 안 되면 방식 변경 제안
⑥ 사용자 확정 → 기록
⑦ 확정본만 고해상도(이미지 2k, 영상 1080p). 같은 프롬프트·같은 참조로
```

- 고해상도는 결과를 "더 좋게" 만들지 않는다. 1080p로 다시 뽑자 새 결함(현관문에 없던 우편 투입구)이 생긴 기록이 있다(E-08).
- 1k 이미지를 1080p 영상으로 바꿔도 그림 자체가 선명해지지 않는다. 한 컷을 720p·1080p로 비교해 보고 정한다.
- 영상의 최종 고해상도판은 채택본을 원본 영상으로 넣고 같은 요소·같은 음성으로 다시 렌더한 작품이 있다(The Prompter). 새로 생성하지 않는다.

## 2. 검수 — 눈으로 보는 것과 숫자로 재는 것

**눈으로 (항목별 ✔/✘)**: 지시한 요소가 다 있는가, 없어야 할 것이 없는가(인원 수, 소품 수, 글자), 좌우, 시선, 의상, 시대 착오, 그림체가 기준 컷과 같은가.

**숫자로 (재면 보고에 숫자를 쓴다. 안 쟀으면 "추정")**

| 지표 | 어떻게 | 기준 예(나부코 작업) |
|---|---|---|
| 전체/구역 밝기 | 0~1 평균 | 컷마다 목표 범위를 정한다(예: 0.45~0.50). 이웃 컷과 비교 |
| 요소 위치 | 화면 % (위에서, 폭) | 크롭 띠·가림 구역 안/밖 판정 |
| 가장자리 비율(과밀 질감) | 에지 픽셀 비율 | 수채 기준 2~8%. 13~22%면 과밀(해칭·로우폴리) |
| 구조 일치도 | 기준 이미지 대비 SSIM | "그대로 유지" 편집이면 0.9 이상 |
| 하이라이트 | 거의 흰 픽셀 비율 | 0.1% 이하(수채) |
| 영상 카메라 움직임 | 광학 흐름으로 누적 확대·이동 | 요청 "약 2배"가 3.56배로 나온 적 있음 — 요청량의 절반으로 쓴다 |
| 영상 속도 균일성 | 1초당 변화량 | 일정해야 함(끝 프레임 넣은 30초 영상은 5배로 가속) |
| 질감 떨림 | 연속 프레임 차이 | 갑자기 생기거나 사라지는 나무·새 확인 |

- 숫자가 "통과"여도 사용자가 "비어 보인다", "단조롭다"고 하면 그게 판정이다. 숫자는 원인을 찾는 데 쓴다.
- 사용자가 보낸 화면 사진은 모니터 촬영본이면 색·밝기가 틀어진다. 비교만 하고 참조로 쓰지 않는다(E-21).

## 3. 재시도 한도와 방향 전환

- 같은 이미지·같은 실패: **2회**. 3회째 전에 멈추고 승인받는다.
- 같은 핵심 실패가 **연속 2회 또는 최근 4회 중 3회** → 문장 추가 금지. 다음 중 하나:
  1. 샷을 둘로 쪼갠다(긴 대사 6줄 30초 → 2줄 20초 + 나머지 연장)
  2. 사건을 뺀다(문이 열리는 장면 삭제, 컷 삭제)
  3. 개념을 단순화한다(다른 얼굴 요소 빼고 효과 방식 변경)
  4. 모델 대신 직접 편집(하늘 이식, 물체 지우기)
  5. 후반 작업으로 넘긴다

## 4. 모델에게 맡기지 말고 후반으로 넘길 것

정확한 이동 거리, 정확한 등장·퇴장 타이밍, 작고 어두운 풀의 흔들림, 별 반짝임, 칠해진 빛줄기의 회전, 컷 사이 디졸브, 새 떼 같은 작은 반복 객체의 경로(오버레이 소재로 따로 만들어 편집에서 이동), 색 맞춤(컬러 그레이드), 하단 그라디언트.

## 6. 크레딧 절약 규칙

1. 영상은 **확인용 저해상도·짧은 길이**로 먼저. 확정 후에만 1080p.
2. 생성 전에 **견적**을 확인한다(도구가 비용 조회를 지원하면 사용).
3. 한 번에 여러 장(배치 4장)을 뽑지 않는다. 한 장 보고 결정한다 — 동시 4장 생성이 반복된 날이 있었다.
4. **2회 규칙**(§3). 같은 날 같은 컷 영상이 10회를 넘으면 그 자체가 경보다.
5. 생성은 반드시 **프로젝트 폴더 안에서**. 폴더 밖 생성은 무엇을 왜 만들었는지 추적이 안 되고 같은 실수를 되풀이하게 한다(E-38).
6. 업스케일(특히 Topaz Video 클라우드)은 필요한 최종본에만. 로컬 앱을 쓸 수 있으면 로컬로.
7. 새 장소는 영상으로 찾지 말고 **이미지로 먼저 확정**(이미지 2.5 vs 영상 20~100).
8. 프롬프트 요청에는 생성하지 않는다(E-02) — 묻지 않은 생성 1회가 고해상도면 100크레딧이 넘는다.
9. 확정본을 "조금 더 좋게" 다시 돌리지 않는다.
10. 매 세션 끝 핸드오프에 그 세션의 생성 횟수·크레딧을 적는다. 총괄은 컷별 누적을 본다.
