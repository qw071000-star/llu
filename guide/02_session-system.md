# 02 세션 운영 — 총괄 세션 하나 + 컷 세션 여럿

목표: 새 세션을 열 때마다 같은 설명을 반복하지 않고, 세션 사이에서 결정이 새거나 뒤집히지 않게 한다.
원칙은 하나다. **기억은 문서에 두고, 세션은 쓰고 버린다.**

---

## 1. 문서 층 — 무엇을 항상 읽고 무엇을 필요할 때만 읽나

| 층 | 문서 | 언제 읽나 | 크기 기준 |
|---|---|---|---|
| L0 지침 | `guide/00_project-instructions.md` (프로젝트 지침 칸 / `CLAUDE.md`) | 항상(자동) | 4천 자 안팎 |
| L1 프로젝트 정본 | `decisions.md` 확정 사항 · `asset-registry.md` 에셋 대장 · `shot-list.md` 컷 목록 | 총괄: 매 세션 / 컷: 컷 카드에 필요한 줄만 | 각 1만 자 이하, 현재 상태만 |
| L2 작업 가이드 | `guide/01~07` | 그 작업을 할 때 해당 문서만 | 문서당 1~2만 자 |
| L3 컷 카드 | `cuts/C##.md` (또는 대화에 붙인 패킷) | 그 컷 세션만 | 3천 자 이하 |
| L4 기록 보관 | `log/` 시행착오·옛 프롬프트·검수 측정값 | 거의 읽지 않음. 원인 조사 때만 | 제한 없음 |

**L1에는 "지금 유효한 것"만 둔다.** 경위·시행착오·폐기된 프롬프트는 L4로 옮긴다. 한 문서에 266번 고친 이력을 계속 쌓거나 리뷰 로그가 80만 자를 넘으면, 세션마다 그걸 읽느라 토큰이 새고 옛 결정과 새 결정이 섞인다(E-39).

**정본은 하나다.**
- 미디어(이미지·영상)의 정본 = Higgsfield 프로젝트에 저장된 요소/결과. 생성은 반드시 프로젝트 폴더 안에서 한다(폴더 밖 생성은 나중에 추적이 안 된다 — E-38).
- 글(결정·설명문·프롬프트)의 정본 = 프로젝트 문서. 대화창은 정본이 아니다.
- 다른 곳(JSON, 콘티 사이트 등)에 사본을 둬야 하면 "어느 쪽이 이기는가"를 `decisions.md` 첫 줄에 적는다(E-11).

## 2. 총괄 세션 (Master)

**하는 일**
- 작품 전체: 구간·컷 순서·길이·화면비·크롭·가림 구역(자막·합창단 등)·시대·그림체 기준.
- `decisions.md`, `asset-registry.md`, `shot-list.md` 관리 — 이 세 문서를 고치는 것은 총괄만 한다.
- 인물 시트·장소 마스터·그림체 기준 같은 **공통 에셋**을 확정한다(컷마다 따로 만들면 일관성이 깨진다).
- 컷 카드 발행 → 컷 세션에 넘긴다.
- 컷 세션의 핸드오프를 받아 검토하고 정본에 반영한다. 인접 컷 이음새(구도·시점·빛·소품 상태)를 점검한다.

**하지 않는 일**
- 한 컷을 반복 생성하는 일(토큰·크레딧이 많이 드는 일은 컷 세션에서).
- 컷 세션이 확정한 결과를 묻지 않고 바꾸는 일.

**시작할 때** (`templates/session-start.md`의 총괄 문구를 붙인다)
1. `decisions.md` → `shot-list.md` → `asset-registry.md` 순서로 읽는다.
2. 받은 핸드오프가 있으면 처리한다(§5).
3. 오늘 할 일과 발행할 컷 카드를 정한다.

---

## 3. 컷 세션 (Cut)

**입력**: 컷 카드 한 장(`templates/cut-card.md`). 컷 카드에는 그 컷에 필요한 확정값·에셋 ID·고정 설명문만 들어 있다. 다른 컷, 전체 시나리오, 옛 시행착오는 넣지 않는다(문맥 격리 — 옛 문장이 프롬프트에 새는 것을 막는다, E-43).

**하는 일**: 그 컷의 퍼스트 프레임 이미지 → 영상 프롬프트 → 생성 → 검수. 사용자 확정까지.

**범위 밖을 발견하면**: 고치지 않고 핸드오프의 "총괄에 올릴 것"에 적는다. (예: 장소 마스터 자체가 틀렸다, 이웃 컷과 구도가 겹친다, 확정 사항과 컷 카드가 어긋난다.)

**끝낼 때**: `templates/handoff.md` 형식으로 보고를 출력한다. 사용자는 그 블록을 총괄 세션에 붙이거나 `log/handoffs/`에 저장한다.

**세션을 새로 여는 기준**: 한 컷이 끝났을 때, 또는 대화가 길어져 앞의 결정이 흐려질 때. 새 세션은 컷 카드 + 마지막 핸드오프만 받으면 이어서 할 수 있어야 한다.

---

## 4. 패킷 — 세션 사이에 오가는 것은 두 가지뿐

| 패킷 | 방향 | 형식 | 핵심 |
|---|---|---|---|
| 컷 카드 | 총괄 → 컷 | `templates/cut-card.md` | 확정값, 에셋 ID+권한, 고정 설명문(글자 그대로), 이 컷 고유의 금지, 완료 조건 |
| 핸드오프 | 컷 → 총괄 | `templates/handoff.md` | 확정된 것(ID), 바뀐 결정, 새로 발견한 실패와 막는 문장, 총괄에 올릴 것 |

- 패킷 첫 줄에 **받는 세션**을 적는다: `받는 세션: 총괄` / `받는 세션: C07`. 한 패킷에 여러 세션 내용을 섞지 않는다.
- 상태 표기: `진행 중` → `컷 확정(사용자 픽스)` → `총괄 반영`. 총괄만 `총괄 반영`으로 닫는다.

---

## 5. 총괄의 핸드오프 처리 순서

1. 핸드오프의 job ID를 Higgsfield에서 직접 열어 확인한다(보고만 믿지 않는다).
2. 확정 사항·에셋 대장과 충돌하는지 본다. 사용자 확정 요구사항을 약하게 만드는 변경은 받지 않고 사용자에게 묻는다.
3. 반영: `shot-list.md` 상태, `asset-registry.md` 확정 job, 새 규칙은 `decisions.md`, 새 실패는 `07_error-registry.md`(공통이면) 또는 프로젝트 오류 표.
4. 이웃 컷 카드에 영향이 있으면(소품 상태, 빛, 마지막 프레임 구도) 그 카드를 고친다.

---

## 6. 토큰·크레딧을 아끼는 운영 규칙

1. L0 지침은 짧게. 세부 규칙은 L2에 두고 "필요할 때 연다".
2. 같은 내용을 두 문서에 쓰지 않는다. 중복은 길이만 늘리고 한쪽만 고쳐 모순을 만든다.
3. 프롬프트 전문은 파일이나 컷 카드에 한 번만 둔다. 대화에 여러 번 다시 붙이지 않고 "바뀐 줄"만 주고받는다.
4. 컷 세션에 전체 시나리오·전 컷 표를 넣지 않는다.
5. 시행착오는 로그로. 정본에는 결론 한 줄과 근거 ID만.
6. 고칠 때는 문서를 다시 타이핑하지 않고 해당 줄만 고친다.
7. 확인은 싸게(1k 이미지·480p·짧은 길이), 확정 뒤에만 비싸게(`06_qa-and-cost.md`).
8. 세션이 길어지면 핸드오프를 쓰고 새 세션으로 넘어간다. 긴 세션은 앞의 결정을 잊고 같은 실수를 되풀이한다.

## 7. 어디에 설치하나

**Claude 앱의 프로젝트(Projects)**
- 지침 칸: `guide/00_project-instructions.md` 내용.
- 프로젝트 지식: `guide/01~07`, `templates/` 중 쓰는 것, 그리고 그 작품의 `decisions.md`·`asset-registry.md`·`shot-list.md`.
- 총괄·컷 세션 모두 같은 프로젝트 안에서 새 대화로 연다. 지식 파일이 공통이라 반복 설명이 필요 없다.
- 정본 문서를 고치면 지식 파일을 교체해야 다른 대화에 반영된다(총괄 세션 끝에 할 일).
- 앱의 대화는 Claude Code 세션이 읽을 수 없다. 정본은 파일로 두고(이 리포 같은 저장소), 대화에만 있는 결정은 그날 파일로 옮긴다(E-41).

**Claude Code (리포)**
- 리포 루트에 `templates/CLAUDE.md`를 복사해 `CLAUDE.md`로 두고, `guide/`·`templates/`를 함께 둔다.
- 작품 정본은 `project/` 아래(`decisions.md`, `asset-registry.md`, `shot-list.md`, `cuts/`, `log/`).
- 여러 세션이 같은 파일을 동시에 고치지 않는다. 같은 파일이 필요하면 총괄이 순서를 정한다.

**동기화가 있는 사이트(예: 콘티 사이트)를 함께 쓸 때**
- 원본이 어디인지(사이트 저장소인지 로컬인지) 먼저 정한다.
- 파일을 직접 고치기 전: 사이트 탭을 모두 닫는다 → 최신 받기 → 백업 → 수정 → 올리기 → 탭 새로 열기. 받기와 올리기 사이를 짧게(E-40).
