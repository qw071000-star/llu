# 세팅 — 키트를 설치하는 사람용

> 팀원은 이 문서를 볼 필요가 없다. 세팅하는 사람이 한 번 하고, 키트가 바뀔 때 다시 본다.
> 팀원용 안내는 `guides/한눈에-보기.md`와 `TEAM-GUIDE.md`에 있다.

## 0. 준비물

| 항목 | 내용 |
|---|---|
| Claude | Pro 이상 요금제. 설정에서 코드 실행(파일 만들기)을 켠다 |
| Higgsfield | 팀 워크스페이스. 생성 크레딧이 여기서 나간다 |
| 키트 파일 | 이 리포의 `kit/`. 앱용 묶음은 `kit/dist/` |
| (Claude Code만) | `python3`, `ffmpeg`/`ffprobe` (`assembly`·`color-continuity` 스킬이 쓴다) |

키트를 고친 뒤에는 `kit/pack-skills.sh`를 실행해 `kit/dist/`를 다시 만든다.

## 1. Higgsfield

1. 팀 워크스페이스를 만들고 팀원을 초대한다.
2. 작품 프로젝트는 만들지 않아도 된다. 첫 대화에서 Claude가 `project-setup`으로 프로젝트와 폴더를 만든다(만들어도 된다고 답하면).
3. 이미 프로젝트가 있으면 이름과 ID를 적어 둔다. 2-3단계의 "This project" 칸에 넣는다.

## 2. Claude 앱 (claude.ai)

### 2-1. 스킬 올리기
설정의 스킬 메뉴에서 "Upload a skill"로 `kit/dist/`의 zip을 하나씩 올린다. 압축은 풀지 않는다.

| zip | 비고 |
|---|---|
| `project-setup.zip`, `production-session.zip`, `higgsfield-generation.zip`, `image-prompt.zip`, `video-prompt.zip`, `acting.zip`, `shot-design.zip`, `edit-planning.zip`, `midjourney-prompt.zip` | 앱과 Code 둘 다 |
| `assembly.zip`, `color-continuity.zip` | Claude Code에서만 동작한다(로컬 ffmpeg가 필요하다). 앱에는 올리지 않아도 된다 |

스킬은 계정마다 올린다. 팀원도 각자 올려야 한다.

### 2-2. 커넥터
설정 → 커넥터에서 연결한다. 각자 자기 계정으로 로그인한다.

| 커넥터 | 하는 일 |
|---|---|
| Higgsfield | 생성과 저장. 목록에 없으면 커스텀 커넥터로 추가한다(주소는 higgsfield.ai의 MCP 안내) |
| Claude Docs (또는 Google Drive / Notion) | 정본을 팀과 같이 쓴다 |
| ElevenLabs | 대사·효과음을 따로 만들 때만 쓴다 |

### 2-3. 작품 프로젝트
1. 새 프로젝트를 만든다. 이름은 작품명으로 한다.
2. **지침 칸**에 `kit/dist/project-instructions.md` 내용을 통째로 붙인다.
3. 붙인 글 맨 위 "This project" 칸을 채운다(지침은 영어다): Title = 작품명, Higgsfield project = 프로젝트 이름과 ID, Canon location = 정본 위치(Doc 링크). 모르면 비워 둔다. 첫 대화에서 Claude가 채울 줄을 보여 준다.
4. **프로젝트 지식**에는 시나리오·콘티만 넣는다. `reference/`, `archive/`, `tests/`, `guides/`(특히 옛 한국어 지침 `guides/지침-한국어/`)는 넣지 않는다(옛 문장이 프롬프트로 새고, 옛 지침과 새 지침이 부딪친다).
5. 팀원에게 프로젝트를 공유한다. 공유가 안 되는 요금제면 팀원이 같은 방법으로 각자 만든다.

### 2-4. 정본
정본(확정 사항, 에셋·폴더 대장, 컷 목록, OK 대장, 컷 카드, 핸드오프)은 한 곳에 둔다.
- 권장: Claude Doc 하나에 탭으로 나눈다. 틀은 `kit/project-files/`에 있다.
- 팀원 모두에게 편집 권한을 준다.

### 2-5. 공용 계정으로 쓸 때 (Claude 계정 1개 · Higgsfield 계정 1개를 여러 명이 돌아가며 사용)

이 방식이면 팀원마다 설치할 것이 없다. 스킬(zip 9개)과 커넥터는 그 계정에 한 번만 올리고 연결한다.

| 할 일 | 방법 |
|---|---|
| Higgsfield | 그 계정의 워크스페이스에 작품 프로젝트를 하나 만든다. 모두 같은 폴더에 저장한다. 크레딧도 한 곳에서 나간다 |
| 정본 | Claude Docs 문서 **하나**. 프로젝트 지식에는 정본 파일을 올리지 않는다(프로젝트마다 복사본이 생겨 어긋난다) |
| 프로젝트를 여러 개 만들 때 | 지침 칸은 **전부 같은 글**을 붙인다. "This project" 칸(작품명, Higgsfield 프로젝트 ID, 정본 Docs 링크)도 같게 한다. 지침을 바꾸면 프로젝트마다 다시 붙인다 |
| 정본에 적기 | `확정 사항` §7의 `운영 방식` 줄에 `공용 계정`과 사용자 이름들을 적는다. 새 작품 시작 질문 9번이 묻는다. 이렇게 적어야 Claude가 `shared-account.md` 규칙을 따른다 |

**Claude가 따르는 규칙** (`kit/skills/production-session/shared-account.md`)
1. 대화 첫 말에 이름을 말한다(`나는 지수`). 이름은 컷 목록 `담당` 칸, 핸드오프, OK 카드에 남는다.
2. 컷을 시작하기 전에 `담당`과 `상태`를 본다. 다른 사람이 `진행`·`검토` 중이면 먼저 묻는다.
3. 확정 사항과 에셋 대장은 총괄 한 명만 고친다. 나머지는 자기 컷 줄, 카드, OK 카드, 핸드오프만 고친다.
4. 승인(OK)한 카드는 고치지 않는다. 정정은 `정정(날짜 · 이름)` 한 줄을 더하고, 바꾸려면 새 테이크로 새 카드를 쓴다.
5. **시작 이미지와 영상의 프롬프트는 한 쌍으로 저장한다**: `3-1 시작 이미지` 카드와 `3-1 영상` 카드에 각각 보낸 프롬프트 전문이 있고, 서로를 가리킨다.
6. 작업이 시작된 컷의 번호는 바꾸지 않는다. 새 컷은 장면의 맨 뒤 번호를 쓴다.
7. 에셋을 바꾸고 싶으면 컷 담당자가 직접 고치지 않고 핸드오프로 올린다. 영향받는 컷 목록은 Claude가 뽑는다.
8. 크레딧은 한 곳에서 나가므로 보내기 전에 견적을 확인한다. 하루 상한을 `확정 사항`에 적어 두면 Claude가 넘기 전에 묻는다.

**주의:** 계정 하나를 여러 명이 쓰면 Claude 사용량 한도도 함께 줄어든다. Claude와 Higgsfield 모두 계정 공유를 약관이 제한할 수 있으니 확인한다. 문제가 되면 Team 요금제와 Higgsfield 팀 워크스페이스로 바꾸고 2-1~2-4를 따른다.

## 3. Claude Code (작품 리포)

가장 쉬운 방법: `guides/설치-프롬프트.md`의 프롬프트를 작품 폴더의 Claude Code에 붙인다. 아니면 작품 폴더에서 `bash <이 리포>/kit/install.sh .`를 직접 실행한다. 정본과 채운 "This project" 칸은 덮어쓰지 않는다. 아래는 그 스크립트가 하는 일이다.


```bash
mkdir -p .claude project/cuts project/log media
cp kit/instructions.md .claude/instructions.md
cp -r kit/context .claude/context
cp -r kit/skills .claude/skills
cp kit/project-files/CLAUDE.md CLAUDE.md
cp kit/project-files/settings.json .claude/settings.json
cp kit/project-files/{decisions,asset-registry,shot-list,ok-cuts}.md project/
printf "tmp/\nmedia/\n" >> .gitignore
```

- `CLAUDE.md`가 항상 읽을 세 파일(지침, `context/tasks.md`, `context/must-ask.md`)을 불러온다.
- `.claude/settings.json`은 검사 스크립트, 조립·색 스크립트, `tmp/` 지우기만 승인 없이 돌게 한다. 다른 권한은 넣지 않았다.
- 처음 한 번은 그 폴더에서 `claude`를 대화형으로 실행해 "이 폴더를 믿는가" 창을 승인한다. 승인하지 않으면 `settings.json`의 허용이 무시된다.
- Higgsfield 커넥터는 Claude Code의 MCP 설정에서 따로 연결한다.
- `media/`에는 Higgsfield에서 내려받은 영상을 둔다. 용량이 커서 git에 넣지 않는다.

## 4. 됐는지 확인 (5분)

새 대화에서 아래를 차례로 말해 본다. 생성은 하지 않으니 크레딧이 나가지 않는다.

| 말 | 이렇게 나오면 된다 |
|---|---|
| "오늘 뭐 하면 돼?" | 정본을 읽고 할 일 후보를 보인다(새 작품이면 질문 14개를 표로 한 번에) |
| "3-2 영상 프롬프트 만들어" | 바로 쓰지 않고, 확인할 것 몇 개를 제안값과 함께 묻는다 |
| "그대로" | 프롬프트와 위험 목록을 보이고, 생성은 하지 않는다 |

프롬프트를 보일 때 검사 스크립트가 돌아야 한다. Claude Code는 승인 창 없이 돈다. Claude 앱은 업로드한 `higgsfield-generation` 스킬 폴더의 `check_prompt.py`를 코드 실행으로 돌린다(확인 방법: `guides/설치-프롬프트.md` §2의 확인 글 5번).

## 5. 키트가 바뀌었을 때

1. 이 리포를 받는다(`git pull`).
2. `kit/pack-skills.sh`로 `kit/dist/`를 다시 만든다.
3. 바뀐 zip만 다시 올리고, `project-instructions.md`가 바뀌었으면 지침 칸을 통째로 바꾼다("This project" 칸은 다시 채운다).
4. Claude Code 리포는 `bash <이 리포>/kit/install.sh .`를 다시 실행한다. `instructions.md`(This project 칸은 유지), `context`, `skills`, `settings.json`만 바뀌고 `project/`(정본)는 그대로다.
5. 팀원에게 바뀐 것을 알린다. 무엇이 바뀌었는지는 `git log`에 있다.
