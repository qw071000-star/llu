# 알아 둘 것 — 실제로 써 보기 전에

> 이 키트를 78개 시나리오로 시험하면서 알게 된 "Claude가 실제로 이렇게 움직인다"와 "그러니 이렇게 쓰면 된다"를 모았다.
> 처음이면 `guides/한눈에-보기.md` → 이 문서 → `guides/할일-목록.md` 순서로 보면 된다.

---

## 1. Claude가 하는 일과 하지 않는 일

| Claude는 | 그래서 사용자는 |
|---|---|
| **"이미지로 만들어", "영상으로 만들어", "보내"라고 해야만 생성한다.** "그대로", "좋아", "진행", "OK"는 생성이 아니다. "보낼까요?" 바로 뒤에 "그대로"라고 해도 보내지 않고 다시 묻는다 | 프롬프트를 본 뒤, 보내고 싶을 때 정확히 그 말을 한다 |
| **결과 이미지·영상을 직접 보지 못한다.** 프롬프트와 Higgsfield 기록으로 짐작하고, 짐작한 것은 "추정"이라고 쓴다 | 결과가 이상하면 무엇이 이상한지 말해 준다(아래 3번) |
| **정본이 대화보다 우선이다.** 확정 사항·컷 목록·OK 대장에 있는 것을 따른다 | 작품 전체 규칙을 바꾸려면 "작품 전체로"라고 말한다. 아니면 "이 컷만"으로 처리한다 |
| **다른 컷의 카드·핸드오프를 열지 않는다.** 옛 문장이 프롬프트로 새는 것을 막기 위해서다 | 다른 컷을 기준으로 하려면 "3-1처럼"이라고 말한다. 그때는 승인된 OK 카드 하나만 연다 |
| **한 생성에 한 가지만 바꾼다.** 여러 개를 말하면 순서를 나눠 준다 | 급해도 한 번에 하나씩 확인하는 편이 결국 빠르다 |
| **정본에 있는 것은 다시 묻지 않는다.** 모델·해상도·화면비·소리·저장 폴더·렌즈가 해당한다 | 바꾸고 싶으면 먼저 말한다 |

## 2. 말하는 법

- **답 첫 줄을 보면 Claude가 무엇으로 이해했는지 안다.** 예: "13번 실사·인물 영상으로 진행합니다." 번호가 틀렸으면 "아니, 11번"처럼 번호로 바로잡는다. 번호는 `guides/할일-목록.md`에 있다.
- **두 작업으로 읽히면 먼저 묻는다.** 예: "3-2에서 손 잡게"는 새 영상인지, 이미 손을 잡은 첫 장면인지 묻는다. 맞으면 "응", 아니면 번호를 말한다.
- **"컷 번호 + 작업 이름"으로 말하면 가장 빠르다.** "3-2 영상 프롬프트", "3-4 퍼스트 프레임", "할아버지 인물 시트".
- **막연하게 말해도 된다.** "구름 더 느리게", "50대처럼", "좀 더 영화같이"라고 하면 Claude가 구체적인 값을 제안한다. 괜찮으면 "그대로"라고 한다.
- **방향은 화면에 보이는 기준으로 말한다.** "왼쪽"은 화면 왼쪽이다. 인물 자신의 손이면 "손녀 입장에서 오른손"처럼 말하면, Claude가 화면 기준으로 바꾸고 "추정"이라고 적는다. "동쪽" 같은 방위는 쓰지 않는다.
- **질문에는 바꿀 것만 답해도 된다.** 답하지 않은 항목은 제안값으로 간다. "몰라", "알아서"도 제안값이다.
- **여러 작업을 한 번에 말하면** Claude가 순서를 정해 첫 것만 하고, 나머지는 왜 기다리는지 한 줄씩 알려 준다.

## 3. 결과가 이상할 때

- **"이상해"만 말하면** Claude가 후보 두세 개(어느 구간, 어느 인물)를 보여 주고 고르게 한다. 바로 말해 주면 더 빠르다. 예: "0:04쯤 할아버지 입이 움직여", "손녀가 너무 빨리 돌아".
- **"너무 빨라", "구름 느리게" 같은 속도 지적**은 지금 구간의 초를 세서 바꿔 준다. "천천히"는 지금보다 긴 구간이 된다.
- **이미지가 "가짜 같아", "AI 같아", "너무 매끈해"면** 노출 → 선명함 → 피부 → 색 → 너무 깨끗함 순서로 원인을 짚고 하나만 고친다. 증상을 말하면 그 항목부터 본다. "매끈해"는 피부, "쨍해"는 색이다. 사실감을 내려고 어둡게 하거나 카메라를 기울이지는 않는다.
- **같은 실패가 두 번 나면 Claude가 멈춘다.** 문장을 더 넣지 않고, 샷을 나누거나 후반 작업(편집·합성)을 제안한다. 이때는 그 제안을 받는 편이 낫다. 세 번째도 같은 결과가 나올 가능성이 높다.
- **승인된 컷을 고치려 하면** "새 테이크로 바꿀까요?"라고 먼저 묻는다. 기존 OK는 새 결과가 승인될 때까지 그대로 둔다.

## 4. 크레딧 아끼기

- **확인은 이미지 1k, 영상 480p로 한다.** 고해상도는 확정한 뒤에만 쓴다. 인물 시트만 예외로 처음부터 2k다.
- **Seedance 영상은 480p를 draft로 보낸다.** 승인하면 7일 안에 같은 테이크를 1080p로 올릴 수 있다. 다시 생성하면 다른 테이크가 나오니, 1080p는 "1080p로"라고 해서 올린다.
- **Claude는 받은 견적만 숫자로 쓴다.** 정본에 비용 메모가 없으면 보내기 전에 견적을 받는다. 숫자가 없으면 "알 수 없음"이라고 쓴다.
- **"크레딧 얼마나 썼어?"**는 컷 목록의 생성/크레딧 칸에 기록된 것만으로 답한다.

## 5. 팀으로 일할 때

- **정본은 한 곳에 둔다.** Claude Doc 하나나 리포의 `project/`. 팀원 모두가 같은 정본을 본다.
- **컷을 끝내면 "핸드오프 써"라고 한다.** 총괄(오늘 할 일을 정하는 사람)이 그걸 받아 정본에 반영한다.
- **팀원이 만든 컷**은 카드가 없어도 Higgsfield job으로 원래 프롬프트를 찾는다. 다른 계정에서 만들어 프롬프트가 비어 있으면, Claude가 그렇다고 알리고 무엇을 기준으로 할지 묻는다.
- **스킬은 계정마다 올린다.** 팀원도 각자 zip을 올려야 한다(`guides/세팅.md` 2-1).

## 6. Claude 앱과 Claude Code

| | Claude 앱 | Claude Code |
|---|---|---|
| 스킬 | zip 7개를 업로드 | `kit/skills/` 폴더 복사, 9개 |
| 마지막 프레임 뽑기·러프컷·색 맞추기 | 안 됨(컴퓨터의 ffmpeg가 필요) | 됨 |
| 정본 | Claude Doc 권장 | 리포 `project/` |
| 처음 할 일 | 지침 칸에 `kit/dist/project-instructions.md` 붙이고 "This project" 칸 채우기 | 작품 폴더에서 `claude`를 한 번 대화형으로 실행해 "이 폴더를 믿는가" 승인. 안 하면 검사 스크립트가 돌 때마다 승인 창이 뜬다 |
| 시험 상태 | **시험하지 못함.** 처음 한 번 `guides/세팅.md` 4번 "5분 확인"을 해 본다 | 78개 시나리오로 시험함 |

## 7. 알려진 약점

이번 시험에서 아직 가끔 나오는 것들이다. 보이면 알려 주면 된다.

- **도구를 쓰는 사이에 영어 한 줄이 섞일 때가 있다.** 예: "Now the cut card…". 답의 본문과 질문은 한국어다.
- **작업 번호를 처음에 잘못 고른 뒤 바로 정정할 때가 있다.** 예: 15번 → 14번. 내용은 정정한 번호대로 진행한다.
- **두 사람이 나오는 컷에서 사건 수를 적게 셀 때가 있다.** "사건이 3개를 넘으면 샷을 나눈다"가 규칙이니, 동작이 많아 보이면 "샷 나눠야 하지 않아?"라고 물어보면 된다.
- **시험은 Higgsfield를 흉내 낸 환경에서, Sonnet 모델로 했다.** 실제 결과물의 품질, 다른 모델에서의 동작은 직접 써 보며 확인해야 한다.

## 8. 키트를 고칠 때 (관리자)

- AI가 읽는 파일(`kit/`)은 영어로 고친다. 사용자에게 하는 한국어 문장, 사용자 말 예시, 정본 칸 이름만 한국어다. 옛 한국어 지침(`guides/지침-한국어/`)은 참고용이고 고치지 않는다.
- 고친 뒤에는 두 가지를 돌린다.
  - `python3 tests/run_kit_tests.py` (자동 점검)
  - `bash kit/pack-skills.sh` (zip과 지침 합본 다시 만들기)
- 바뀐 zip만 다시 올리고, 지침 합본이 바뀌었으면 지침 칸을 통째로 바꾼다(`guides/세팅.md` 5번).
- 기능 목록은 `guides/주요-기능.md`, 기능별 점검 결과는 `tests/agent-eval/results/feature-check.md`에 있다.
