# 15블록 가이드 — 실사·인물 영상 프롬프트

> 사람(제작자·팀원)이 읽는 안내서다. Claude가 읽는 규칙은 `kit/skills/video-prompt/`에 있다.
> 이 문서는 그 규칙을 블록별로 풀어 쓴 것이다. 규칙이 서로 다르면 키트가 맞다.
> 근거: `kit/skills/video-prompt/SKILL.md`, `live-action.md`, `fixes.md`, `kit/skills/acting/SKILL.md`, `reference/error-registry.md`, `reference/higgsfield-history.md`, `reference/kit-test-report.md`.

---

## 0. 개요

**15블록은 실사·인물 영상 프롬프트의 고정 틀이다.** Seedance 2.5 같은 영상 모델에 보내는 영어 프롬프트를 15개의 제목 블록으로 나눠 쓴다. 「어머니와 고등어」에서 확정된 영상 6개는 모두 "시작 이미지 + 단일 테이크 + 고정 카메라 + 사건 1~3개" 조합이었다. 15블록 구조가 자리 잡은 뒤 성공률이 올랐다(`reference/higgsfield-history.md` §2).

**언제 쓰나**

| 컷 | 형식 | 키트 파일 |
|---|---|---|
| 인물이 나오는 실사 컷(대사·동작·연기) | 15블록 | `kit/skills/video-prompt/live-action.md` |
| 배경·풍경·그림체 컷(인물 연기 없음, 시작 이미지가 장면을 다 담음) | 4문단(`Camera` / `Motion` / `Keep` / `Silent`) | `kit/skills/video-prompt/background.md` |
| 승인한 테이크를 1080p로 | 재렌더 틀 | `kit/skills/video-prompt/rerender.md` |

**지킬 것**
- **순서와 제목은 고정이다.** 쓸 게 없는 블록도 제목은 남긴다. 검사 스크립트가 빠진 제목과 바뀐 순서를 잡는다.
- **"짧은 판"은 없다.** 15블록 고정을 깨던 짧은 판은 키트에서 지웠다(`reference/kit-test-report.md` §2).
- **`PRE_SHOT_CONTINUITY`는 0번 블록이다.** 앞 숏에서 이어받는 상태가 있을 때만 맨 앞에 둔다. 없으면 블록째 뺀다.
- **프롬프트 본문은 영어, 대화는 한국어다.** 블록 밖 일반 줄(한국어)에 화면비, 소리, 시작·끝 이미지 job, 붙인 요소(순서대로), 위험 목록을 적는다.
- **시작 이미지가 없으면 15블록을 쓰지 않는다.** 그 컷 전용 퍼스트 프레임부터 만든다. 다른 컷의 시작 이미지를 쓰지 않는다(`kit/context/must-ask.md` "실사·인물 영상").

**사건 수가 성패를 가른다.** 글자 수보다 중요하다. 한 생성에 사건은 1~3개다. 동사마다 센다. 이 기준은 블록 전체에 걸친다(→ §16).

## 방향은 모두 화면 기준이다

15블록에서 가장 자주 틀린 것이 방향이다. 「고등어」에서 "화면 오른쪽 손"이 네 번 연속 인물 자신의 오른손으로 읽혔다(E-14). 그래서 키트는 모든 방향을 **화면(카메라) 기준 + 화면 속 물건**으로 쓴다(`kit/instructions.md` 규칙 6).

- 인물이 나오는 프롬프트에는 이 문장을 글자 그대로 넣는다.
  `LEFT and RIGHT are SCREEN directions, never the character's own left or right.`
- 짧은 형(`LEFT and RIGHT are SCREEN directions.`)은 검사 스크립트가 경고한다.
- 동서남북, 인물 기준 좌우(`his right hand`), 카메라 기준(`nearer the camera`)은 쓰지 않는다.

| 대상 | 쓰지 않는다 | 쓴다 |
|---|---|---|
| 손 | `his right hand`, `오른손` | `the screen-left hand, nearer the cabinet` |
| 손(옆모습) | `the hand nearer the camera`, `road-side hand` | `the screen-left hand, farther from the sign` |
| 빛 | `light from the west` | `the dominant source comes from screen left, the window side` |
| 돌아서는 쪽 | `turns to her left` | `turns toward screen right, toward the door` |
| 문 경첩 | `hinged nearer the camera` | `hinged on the edge nearer the wardrobe` |

- **사용자가 "왼쪽", "오른손"이라고 해도 화면 기준으로 본다.** 사용자가 "인물 입장에서 오른손"이라고 밝히면, 인물이 향한 쪽으로 화면 쪽을 정하고 "추정"이라 적는다.
- **반대쪽을 보는 카메라는 좌우가 뒤집힌다.** 장소 뷰의 왼쪽 랜드마크와 광원이 화면 오른쪽으로 간다. 가져온 OK 줄의 손·돌아서는 쪽·빛도 이 뷰에 맞게 바꾼다(`kit/skills/production-session/ok-reuse.md` §3의 5). 시험 C33에서 빛 방향을 안 뒤집어 실패했다.

## 블록별 설명

각 블록은 같은 순서로 적는다. 들어가는 것 / 예시 문장 / 주의사항 / 누가 채우나·어디서 가져오나.
"컷 카드 [N]"은 `kit/skills/production-session/cut-card.md`의 칸 번호다. "에셋 대장"은 `asset-registry.md`, "연속성 표"는 `shot-list.md` 안의 표다.

### 0. `PRE_SHOT_CONTINUITY`

**들어가는 것** 앞 숏에서 이어받는 상태다. 위치, 자세, 소품 소유, 빛. 이어받지 않는 것은 지금 상태로 적는다.

**예시 문장**
```text
the bag is closed
```

**주의사항**
- 앞 숏을 가리키는 말(`previous shot`, `same as before`, "앞과 같음")은 쓰지 않는다. 모델은 앞 숏을 모른다. 상태를 직접 쓴다. 검사 스크립트가 경고한다.
- 이어받는 상태만 쓴다. 앞 영상의 프레이밍·렌즈는 가져오지 않는다(`SKILL.md` §2 "이어 붙이기").
- 확인 없이 계승하는 것이 흔한 실수다. 연속성 표와 앞 컷 끝 상태를 대조한다.
- 이어 붙이는 생성이면 뒤 생성은 앞 생성의 지정 프레임을 `start_image`로 받는다. 뒤 생성의 0:00은 콘티 시간 그대로이고 앞에 여백을 두지 않는다.

**누가 채우나** 컷 카드 [6] "이음새: 앞 컷에서 이어받는 것". 앞 컷 끝 상태는 연속성 표에서 가져온다.

### 1. `SCENE_CONTEXT`

**들어가는 것** 시대, 장소, 시간대, 이 클립에서 일어나는 일. 2~4문장. 이 클립의 일만 쓴다.

**예시 문장** (틀)
```text
[Era]. [Place, time of day]. [What happens in this clip, 2–4 sentences, only this clip.]
```

**주의사항**
- 카메라·연기를 여기 몰아 쓰지 않는다. 그것은 7번·9번 블록 자리다.
- 이 샷에 나오지 않는 인물, 태그, 씬 번호는 넣지 않는다. `as in shot 3-1` 같은 컷 번호는 모델이 모른다. 검사 스크립트가 경고한다.
- 한 생성에 한 장소다. 한 클립에서 장소가 세 번 바뀌자 로우폴리 절벽·고전 신전이 생겼다(E-26). 새 장소는 먼저 이미지로 확정한다.

**누가 채우나** 컷 카드 [1] 목표, `decisions.md`의 시대·장소, 컷 목록의 그 컷 줄.

### 2. `ACTIVE_REFERENCES`

**들어가는 것** 붙인 참조마다 ID·역할·권한 한 줄. 시작 이미지도 포함한다. 끝에 `REFERENCE AUTHORITY` 문단으로 권한을 나눈다.
- 시작 이미지 줄: 0:00의 카메라·방·빛·인물 위치가 이 이미지다.
- 인물 줄: 에셋 대장의 고정 설명문(WARDROBE만) + `100% matches the reference`.
- 음성 파일을 붙였으면 `[NAME]'s voice 100% matches audio_[N]`.
- 한 생성에서 의상·헤어 상태가 바뀌면 요소 둘을 붙이고 시간으로 나눈다.
- 일부에만 나오는 참조는 범위를 적는다.

**예시 문장**
```text
<<<[start image ID]>>> START IMAGE: the exact frame at 0:00.
REFERENCE AUTHORITY: the start image has sole authority over camera, framing, the room, furniture,
light, colour and the 0:00 positions. The character references have authority only over faces,
hair, bodies and clothes.
[A] until 0:04, [B] from 0:04
only inside the mirror, only 0:06–0:14
```

**주의사항**
- **태그 수 = 붙인 요소 수.** 안 붙인 태그를 쓰거나, 붙이고 안 쓰는 것이 흔한 실수다. 검사 스크립트 `--refs`가 FAIL로 잡는다.
- 자리표시 태그(`<<<LOC>>>`, `<<<CHAR>>>`)가 남으면 FAIL이다. 꺾쇠는 두고 안의 이름만 실제 요소 이름으로 바꾼다.
- 고정 설명문은 글자 그대로 옮긴다. 시험 C13에서 가방 문장을 바꿔 써서 실패했다. 대장과 OK 카드가 다르면 대장을 따른다.
- 콘티 썸네일·모니터 사진은 붙이지 않는다. 썸네일의 얼굴·옷·주황 톤이 섞였다(E-16). 그 구도가 필요하면 같은 구도의 빈 장소 이미지를 만들어 장소 참조로 쓴다.
- 소품 크기는 소품 참조가 아니라 시작 이미지를 따른다. 흰 배경 봉지 참조를 쓰자 봉지가 상체만큼 커졌다(E-18). 장면 프레임에서 잘라 만든 요소로 바꿔 해결했다.
- 글자 수를 줄일 때는 `REFERENCE AUTHORITY`와 겹치는 권한 설명부터 뺀다(→ §16).

**누가 채우나** 컷 카드 [7] 참조, [8] 고정 설명문 이름. 문장 자체는 에셋 대장(인물 WARDROBE, 소품 고정 설명문). 시작 이미지 job은 퍼스트 프레임 OK 카드. 목소리 문장은 에셋 대장(`acting` §7).

### 3. `LOCATION_MAP`

**들어가는 것** 좌표 문장, 카메라 위치, 전·중·후경, 광원. 고정 물건이 화면 어느 쪽인지 컷마다 다시 쓴다. 문은 열리는 쪽을 물건으로 쓴다. 필요하면 동선(경로, 지나가지 않는 구역).

**예시 문장**
```text
LEFT and RIGHT are SCREEN directions, never the character's own left or right. Places are named by the objects on screen.
hinged on the edge nearer the wardrobe
```

**주의사항**
- "근처에", "그 문"처럼 쓰지 않는다. 위치는 물건과 거리로 쓴다.
- 같은 종류 물건이 둘 이상이면 이름과 위치로 구분한다. 장소 사진에 탁자가 둘인데 구분하지 않아 봉지가 거실 탁자에 놓였다(E-17).
- 장소 정보는 좌표 줄 + 네 줄까지만 쓴다. 카메라, 전·중·후경, 빛, 필요하면 경로다. 길수록 인물 참조가 밀린다.
- 경첩은 물건 기준이다. `nearer the camera`로 쓰지 않는다(시험 뒤 고친 규칙).

**누가 채우나** 에셋 대장의 장소 뷰(MASTER GEOMETRY, 랜드마크), 컷 카드 [4] 카메라 위치, [5] 동선. 경첩 쪽이 없으면 Claude가 묻는다.

### 4. `FIRST_FRAME_AND_SPATIAL_BLOCKING`

**들어가는 것** 0:00에 누가 어디서 무슨 동작 **도중인지**. 몸 방향, 시선, 손. 소품의 위치·상태·든 사람. 보이는 인원 수.

**예시 문장**
```text
(Scope: FIRST_FRAME only.)
[Person] is already in place at 0:00, mid-[action]. No empty establishing frame.
Exactly [one person is / N people are] visible.
```

**주의사항**
- 이 블록은 0:00만 쓴다. 숏 전체로 넓히지 않는다.
- 첫 프레임은 영상의 0:00이다. 시작 이미지와 같아야 한다. C#9에서 시작 이미지가 "고개를 돌린 뒤"를 그려 참조에서 뺐다(E-19).
- 빈 화면으로 시작해 인물이 들어오면 실패다. 첫 프레임부터 정위치, 동작 도중으로 쓴다. 문을 열고 들어오는 등장은 세 번 재생성해도 실패했다(E-34). 등장은 "이미 걷는 중, 문은 뒤에서 닫히는 중"으로 쓴다.
- 0:00 소품 위치를 고정한다. 아내가 봉지를 들고 들어온 테이크가 있었다(`90565927`).

**누가 채우나** 컷 카드 [5] "시작(0:00)". 시작 이미지가 기준이다. 컷 카드와 시작 이미지가 다르면 시작 이미지가 이긴다.

### 5. `FORMAT_MODE`

**들어가는 것** 실사, 단일 연속 테이크, 길이.

**예시 문장**
```text
Live action. A single continuous take from 0:00 to 0:[NN]. No cuts. [NN] seconds.
All movement is slow and even; nothing accelerates suddenly.
hard cuts only at 0:0a; the camera never cuts by itself
```

**주의사항**
- 단일 테이크인데 컷을 요구하는 모순이 흔하다.
- 컷이 필요하면 컷 시점과 컷마다 길이·카메라·첫 프레임 인물·동작을 쓴다. 인물이 컷 사이에서 사라지면 컷을 걷는 도중에 걸고, 그래도 안 되면 컷을 없앤다.
- 길이는 정본의 컷 길이를 따른다. 없으면 대사·동작 실사 5~10초. 15초를 넘으면 나눈다. 30초 영상은 속도 5배 가속·그림체 붕괴·순간이동이 났다(E-25).

**누가 채우나** 컷 카드 [3] 형식(길이). 기본값은 `decisions.md`.

### 6. `OPTICS`

**들어가는 것** 대각 화각(도) + 관찰 결과 3개, 심도·초점 이동.

**예시 문장**
```text
Diagonal field of view about 63°. [A], [B] and [C] are fully visible in one frame / straight
lines stay straight / no telephoto compression.
Diagonal field of view about 29°. The background is compressed and soft / only [person] is
sharp / the camera is physically far away.
```

**주의사항**
- mm·조리개·렌즈 브랜드는 쓰지 않는다. 영상 모델이 듣지 않는다. 검사 스크립트가 경고한다. 장비명은 정지 이미지에만 쓴다.
- 시작 이미지의 mm를 환산표로 바꾼다(풀프레임 기준).

| mm | 24 | 28 | 35 | 50 | 65 | 75 | 85 | 100 | 135 |
|---|---|---|---|---|---|---|---|---|---|
| 대각 화각 | 84° | 75° | 63° | 47° | 37° | 32° | 29° | 24° | 18° |

  표에 없는 mm는 가까운 두 값 사이로 잡는다(105mm ≈ 23°).
- 렌즈는 샷당 하나다. 화각은 컷에서만 바뀐다.
- 얼굴·장소 전체·손 디테일을 한 비트에 섞지 않는다. 섞이면 컷을 나눈다.

**누가 채우나** 컷 카드 [4] 렌즈. 기본은 시작 이미지의 mm다. 사용자가 다르게 말할 때만 Claude가 묻는다.

### 7. `CAMERA`

**들어가는 것** 위치(화면 속 물건으로), 높이, 방향, 고정 여부, 움직임과 속도.

**예시 문장**
```text
Fixed and completely locked from 0:00 to 0:NN. No pan, no tilt, no zoom, no push-in, no reframing.
```

**주의사항**
- 카메라 동작은 한 생성에 하나다. 복합 움직임(팬 + 줌)이 흔한 실수다. 고정 문장과 움직임 단어(dolly, push-in, orbit)가 함께 있으면 검사 스크립트가 경고한다.
- 카메라가 지정 지점이 아니라 가운데로 직진하면 "피사체를 따라가는 추적 촬영"으로 바꾸고 확대량을 원하는 양의 절반으로 쓴다(`fixes.md`).

**누가 채우나** 컷 카드 [4] 카메라. 퍼스트 프레임과 재시도도 같은 값을 쓴다. 값이 바뀌면 카드를 먼저 고친다.

### 8. `ACTION_TIMING`

**들어가는 것** `0:00–0:03 —` 형식의 구간별 행동·대사. 마지막 프레임 상태.

**예시 문장**
```text
0:00–0:0[a] — [state + action, per person].
0:0[a]–0:0[b] — [the line in AUDIO is said once here; what each person's hands do].
0:0[b]–0:[NN] — [continuing state]. The shot ends with [final state].
```

**주의사항**
- **빈 구간을 두지 않는다.** 빈 구간은 모델이 멋대로 채운다. 검사 스크립트가 구간 사이 틈을 잡는다.
- 대사 횟수가 바뀌면 실패다. "exactly once"처럼 횟수를 쓴다.
- 사건 수를 센다(→ §16). 시험 C29에서 "일어나서 가방 들고 돌아 나가"를 3개로 셌다. 나가기도 센다. 4개다.
- "아무 일도 일어나지 않는다"를 구간별로 쓰면 지켜진다. C#8 팬 위 생선 컷은 뒤집지 않음, 손·도구 없음, 김만 조금 늘어남을 구간별로 써서 확정됐다.
- 고개를 돌렸다가 되돌리면 `From then until the end [his] eyes and head stay on [her]. Turning back = forbidden`.
- 몸이 휙 돌면 부위 순서와 초를 쓴다: `head → shoulders → feet over three seconds; turning within one second = failed take`.
- 나가기는 끝 프레임 상태 문장으로 쓴다. 마지막 프레임에 몸 절반이 프레임 밖, 이미 걷는 중, 문은 뒤에서 닫히는 중.

**누가 채우나** 컷 카드 [6] 타이밍(구간·대사 원문·횟수·마지막 프레임), [5] 시선 바뀌는 시점·끝 위치.

### 9. `CHARACTER_ACTING`

**들어가는 것** 인물마다 목표(행동으로), 손의 일, 몸(무게·템포·호흡), 비트 변화(시선·사이·자세), 눈의 삶, 감정 범위의 양 끝 = 실패, 반응하지 않을 사람. 마지막에 `Nobody looks at the camera.`

**예시 문장**
```text
[Range: between X and Y; X = failed take, Y = failed take]
continuous naturalistic eye life: micro-saccades and gaze targeting, the gaze drifting and settling
rather than locking, realistic blink rate tied to state, live wet catchlights, the eyes reaching
the target a beat before the head turns
```

**주의사항**
- **새로 쓰면 `kit/skills/acting/SKILL.md`를 연다.** 시험 C10에서 acting을 열지 않는 실수가 회차마다 나왔다. OK의 연기 줄을 그대로 가져올 때만 열지 않는다.
- 감정 형용사를 쓰지 않는다. 상대를 향한 동사(목표)와 행동을 쓴다. 목표는 `[상대]에게/에게서 + 동사`다. "내색하지 않기"처럼 자기를 향한 것은 목표가 아니다.
- **양 끝을 `failed take`로 닫는다.** 없으면 검사 스크립트가 경고한다. 「고등어」에서 "굳음이 크거나 한숨이면 실패, 반응이 없어도 실패"로 닫은 것이 잘된 방법으로 꼽혔다.
- 눈(eye, gaze)이 없으면 죽은 눈이 나온다. 검사 스크립트가 경고한다.
- 비트는 사건이 아니다. 시선이 옮겨 감, 사이, 숨은 비트다. 사건 수(1~3)는 그대로 두고 비트는 같은 행동 안의 전술 변화로 쓴다. 6초 컷이면 비트 2개면 충분하다.
- 멈춤이 놀람으로 읽히면 `does not startle; simply stops`.
- 연기 안에 의상·카메라·색을 넣지 않는다. 작품 레지스터(`decisions.md` §5)를 넘지 않는다.

**누가 채우나** Claude가 `acting`으로 쓴다. 인물 마스터 프로필은 에셋 대장. 감정 범위의 양 끝은 사용자에게 묻는다. 반응하지 않을 사람은 컷 카드 [5] 시선 줄.

### 10. `PHYSICS`

**들어가는 것** `motion_owner`별 무게·접촉. 인물, 소품, 카메라, 환경을 따로 쓴다. 소품은 상태 머신으로 쓴다.

**예시 문장**
```text
motion_owner = PROP: [state machine, exactly N transitions; weight, contact]
[OBJECT] state: [STATE_A] -> [STATE_B], exactly one transition, never reversed.
```

**주의사항**
- 누가 움직이는지 불분명한 것이 흔한 실수다. 움직임마다 주인을 정한다.
- 환경 사건(문이 저절로 닫힘)이 어색하면 그 사건을 빼고 숏 내내 한 상태로 둔다. C#2 현관 컷은 문 닫힘을 빼고 "숏 내내 닫힘"으로 바꾼 판이 확정됐다.
- 소품이 다른 손으로 가거나 커지면 소품 요소를 붙이고 손(화면 쪽 + 물건), 내려놓지 않음, 크기 = 시작 이미지를 적는다.
- C#6에서 봉지 상태 머신(ON_TABLE→LIFTED→CARRIED 한 번)이 확정됐다.

**누가 채우나** 에셋 대장의 소품 고정 설명문·무게·상태 머신, 컷 카드 [5] 소품 줄(상태 A → B, 어느 손).

### 11. `LIGHTING`

**들어가는 것** 실제 광원 하나를 지배광으로. 방향은 화면 쪽 + 그쪽 물건.

**예시 문장**
```text
[Practical sources as in the start image; the dominant source comes from screen [left/right], the [object] side.]
```

**주의사항**
- 참조 사진 룩으로 단정하지 않는다. 빛은 시작 이미지와 그 뷰의 LIGHT LOCK이 정한다.
- 반대쪽 카메라면 빛 쪽이 뒤집힌다. 그 뷰의 LIGHT LOCK을 쓴다.
- 쓰고 나서 그 뷰의 LIGHT LOCK과 화면 좌우·광원 쪽이 맞는지 본다(`SKILL.md` §0 일관성 점검).

**누가 채우나** 에셋 대장의 그 뷰 LIGHT LOCK(글자 그대로, `--must-include`에도 넣는다).

### 12. `AUDIO`

**들어가는 것** 대사 원문, 횟수, 목소리 문장, 효과음, 음악 여부, 말하지 않는 인물.

**예시 문장**
```text
[PERSON]: "[line]" — [voice sentence, verbatim]. [PERSON 2] does not say a single word:
no attempt to speak, no parted lips, no mouthing.
```

**주의사항**
- Seedance 2.5는 소리가 기본으로 켜져 있다. 그래서 이 블록이 필요하다.
- **말하지 않는 인물의 입을 잠근다.** "말하려다 만다"를 쓰자 입술이 움직였다(E-35). 망설임은 숨·삼킴·손으로 준다. 검사 스크립트가 `about to speak` 같은 말을 경고한다.
- `no lip movement` 같은 약한 문장이 이미 있으면 더하지 말고 위 문장으로 바꾼다. 시험 C18에서 약한 문장을 남겨 실패했다.
- 대사 한 줄에 2~4초를 준다.
- 목소리 문장은 인물마다 하나를 고정해 그대로 붙인다.

**누가 채우나** 컷 카드 [3] 소리, [6] 대사 원문·횟수. 목소리 문장은 에셋 대장. 소리 기본은 `decisions.md`. 대사 유무가 비어 있으면 Claude가 묻는다.

### 13. `STYLE`

**들어가는 것** 매체 질감·색조 한두 줄.

**예시 문장**
```text
[Medium, look, skin tones, saturation.]
```

**주의사항**
- 스타일이 얼굴을 통제한다고 가정하지 않는다. 얼굴은 인물 참조가 맡는다.
- 다른 OK의 색감을 가져올 때 OK 프롬프트에 색 문장이 없으면 그 색은 참조 이미지에서 온 것이다. 문장을 지어내지 않는다.

**누가 채우나** `decisions.md`의 룩 기준. "3-1의 색감으로"면 그 OK의 `STYLE`·`QUALITY` 줄.

### 14. `QUALITY`

**들어가는 것** 해상감, 피부·직물 질감, 손가락 왜곡 억제.

**예시 문장**
```text
Facial features clear; skin and fabric textures natural. No distortion of faces or fingers.
```

**주의사항**
- 글자 수를 줄일 때 장소·스타일 다음으로 줄이는 블록이다(→ §16).
- 재렌더 때는 원본의 `STYLE`·`QUALITY` 문장을 그대로 쓴다(`rerender.md`).

**누가 채우나** 틀 문장. 작품마다 `decisions.md` 룩 기준에 맞춘다.

### 15. `REQUIRED_AND_FORBIDDEN_CONSTRAINTS`

**들어가는 것**
- Required: 지킬 상태·횟수 3~5개, 범위 태그와 함께.
- Forbidden: 실제로 났던 실패만, 범위 태그와 함께. 자막·글자·워터마크·로고 금지는 기본으로 둔다.

**예시 문장**
```text
- [state to keep] ([ENTIRE_SHOT / INTERVAL 0:0a–0:0b / FINAL_FRAME])
- Subtitles, text, watermarks, logos. (ENTIRE_SHOT)
```

**주의사항**
- **과거 실패를 누적하지 않는다.** 금지어가 오히려 그것을 부른다. "no domes"가 돔 화덕을 지울 위험, "옅은 안개가 낮게 깔린다"가 연기 띠를 만든 일이 있었다(E-27). C#2는 금지 15~18개를 넣자 세부가 일부만 지켜졌다.
- 원하는 상태를 먼저 쓰고, 실패는 결과로 쓴다. 금지어는 범위를 좁힌다: `no [X] on [Y]`.
- 예상 위험은 Forbidden이 아니라 Required나 해당 블록 문장으로 막는다.
- 같은 증상을 막는 문장이 이미 있으면 더하지 않고 그 문장을 바꾼다.
- 사용자가 "금지할 것을 다 넣으라"고 하면 범주별로 묶는다(`[Faces and clothing]` `[Camera and editing]` …). 그만큼 사건 수를 더 줄인다.

**누가 채우나** 컷 카드 [10] 난 실패 → 막는 문장, [11] 거절 이유, 에셋 대장 인물의 "알려진 실패", 가져온 OK의 위험(`ok-reuse.md` §3의 4).

## 16. 덜어내는 법

근거: `live-action.md` "덜어내는 법", `SKILL.md` §1·§2.

**먼저 사건 수를 줄인다.** 글자 수보다 사건 수가 먼저다.
- 한 생성에 1~3개. 동사마다 센다. 묶어 세지 않는다.
  - 일어나·들고·돌아서·나간다 = 4
  - 돌아서 걸어와 손을 잡는다 = 3
- 넘으면 합치지 않는다. 샷별 사건 목록을 제안한다.
  - 샷 A: 일어나 가방을 든다 / 샷 B: 돌아서 나간다
- 사건은 몸이나 물건의 상태가 바뀌는 동작이다(쥐기·놓기·일어서기·돌아서기·걷기·대사). 시선, 사이, 숨은 비트라 세지 않는다.
- 인물마다 할 일 하나. 인물이 셋 이상이면 줄이기보다 샷 나누기가 먼저다.

**그다음 글자 수.** 5,500자 이하가 안전했다. 12,000자 프롬프트에서 뒤쪽 금지문이 약해졌다(E-29).

| 순서 | 줄일 곳 |
|---|---|
| 1 | `ACTIVE_REFERENCES`에서 `REFERENCE AUTHORITY`와 겹치는 권한 설명 |
| 2 | 장소(`LOCATION_MAP`은 좌표 줄 + 네 줄까지) |
| 3 | 스타일 |
| 4 | 환경(`QUALITY`·배경 묘사) |
| 5 | 연기 문장 |

- 이 샷에 나오지 않는 인물, 태그, 씬 번호는 뺀다.
- **고정 문장·가져온 OK 줄·연기의 양 끝은 빼지 않는다.** 이것들을 빼야만 줄어들면 줄이지 않고 WARN을 남긴다. 이유에 줄여 본 항목과 글자 수를 적는다.
  - 예: `5,788자 유지: 인물 2·참조 4, 겹친 권한 설명 −300자`
- 인물 2·참조 4면 넘기 쉽다. 시험 C24에서도 5,823자 WARN을 이유와 함께 남겼다.

**두 번 실패하면 멈춘다.** 같은 핵심 실패가 연속 2회, 또는 최근 4회 중 3회면 문장을 더하지 않는다. 샷 나누기, 사건 줄이기, 직접 편집, 후반 작업 중 하나로 간다(`kit/instructions.md` 규칙 8).

## 17. 검사 스크립트 쓰는 법

근거: `kit/instructions.md` "출력 — 검사", `video-prompt/SKILL.md` §4, `kit/skills/higgsfield-generation/check_prompt.py`.

**언제** 프롬프트를 사용자에게 보이기 **전에** 돌린다. 보낸 뒤가 아니다.

**절차**
1. 프롬프트 전문을 작품 리포의 `tmp/` 아래 파일로 저장한다.
2. 고정 문장을 한 줄에 하나씩 `tmp/` 파일로 저장한다. 에셋 대장의 WARDROBE, 소품 설명문, LIGHT LOCK, 좌표 문장, 가져온 OK 줄 전체다.
3. 아래 줄을 단독 Bash 호출로 돌린다. `cd`, `&&`, 파이프, 절대경로를 쓰지 않는다. `.claude/settings.json`의 허용 패턴과 글자가 같아야 승인 없이 돈다.
   ```bash
   python3 .claude/skills/higgsfield-generation/check_prompt.py --kind video tmp/파일 --refs 붙일요소수 --seconds 길이 --must-include tmp/고정문장파일
   ```
4. FAIL은 고친다. WARN은 고치거나, 남길 이유를 숫자와 함께 적는다.
5. 끝나면 `tmp/` 파일을 지운다. 실행이 안 되면 그렇다고 적는다.

**옵션**

| 옵션 | 뜻 |
|---|---|
| `--refs` | 붙일 요소 수. 시작 이미지 포함. 프롬프트의 `<<<…>>>` 태그 수와 다르면 FAIL. 재렌더는 태그 수이고 붙이는 원본 영상은 세지 않는다 |
| `--seconds` | 영상 길이. 15초를 넘으면 WARN. 없으면 프롬프트의 `NN seconds`에서 읽는다 |
| `--must-include` | 이 파일의 줄이 글자 그대로 없으면 FAIL |

**영상에서 잡는 것**

| 잡는 것 | 등급 |
|---|---|
| 채우지 않은 빈칸(`[ ]`, `[NAME]`, 한국어 자리) | FAIL |
| 자리표시 태그(`<<<LOC>>>`) 남음, 태그 수 ≠ `--refs` | FAIL |
| 고정 문장이 글자 그대로 없음 | FAIL |
| 다른 도구 문법(`--ar`) | FAIL |
| 15블록 제목 빠짐, 순서 바뀜 | WARN |
| 길이 5,500자 초과(8,000자 초과는 더 강한 경고) | WARN |
| 시간 구간 사이가 빔 | WARN |
| `CHARACTER_ACTING`에 `failed take` 없음, 눈 없음 | WARN |
| mm·조리개·장비명 | WARN |
| "말하려다" 류 | WARN |
| 고정 카메라 + 움직임 단어 | WARN |
| 인물 기준 좌우, 화면 쪽 없는 손, 동서남북, 좌표 문장 없음·짧음 | WARN |
| 이전 샷·컷 번호를 가리키는 말 | WARN |
| `gradually becomes`, `morphs into` 같은 전환 | WARN |

**스크립트가 못 잡는 것**은 사람이 본다(`SKILL.md` §0 일관성 점검, §4).
- 이 컷의 시작 상태가 앞 컷의 끝 상태와 같은가(위치, 소품 상태, 빛)
- 그 뷰의 LIGHT LOCK과 화면 좌우, 광원 쪽이 맞는가
- 사건 수가 1~3개인가

## 18. 모호한 말을 바꾸는 표

사용자는 대개 모호하게 말한다. Claude는 아래처럼 값·문장으로 바꿔 제안값으로 보인다. 결과 지적이 아니어도 쓴다. 바꾼 줄은 "전 → 후"로 보이고 검사한다. 원문은 `kit/skills/video-prompt/SKILL.md` §0 "모호한 말" 표다.

| 사용자 말 | 바꾸는 법 |
|---|---|
| "구름 더 느리게 / 빠르게" | 그 대상의 `Motion` 줄만 고친다. 이동량(화면 %)을 절반 / 두 배로. 다른 움직임은 그대로 |
| "풀도 흔들리게" | 이미지에 있는 것만 `Motion`에 한 줄 더한다(방향·세기). "사건이 하나 늘었다"고 알린다 |
| "별이 더 반짝이게"(작고 반복되는 요소) | 모델이 잘 못 지킨다고 생성 전에 알린다. 한 번 시도, 2회 실패면 후반 오버레이. 시작 이미지에 없으면 시도하지 않는다 |
| "천천히"(사람 동작) | 기존 구간 초를 먼저 센다. 새 구간은 반드시 더 길다. 사건 수는 그대로. `taking the full [N] seconds. [Action] finished in under [N − 1] seconds = failed take.` 기존 구간이 이미 4초 이상이면 시작을 앞당기거나 영상을 늘리는 안을 묻는다 |
| "걸음이 젊어" | 보폭·팔·발·무게중심으로 쓰고 반대 걸음을 닫는다. `"[name] walk" — [step size], [arm swing], [feet lifted or dragged], [centre of weight]. A [opposite] walk = failed take.` |
| "…하고 …하고 나가" | 동사마다 사건을 센다(§16). 3개를 넘으면 샷 나누기를 제안한다 |
| "왼쪽으로", "오른손에" | 화면 기준으로 쓴다(위 "방향은 모두 화면 기준이다") |
| "이상해", "별로야" | 다시 만들라는 말이 아니다. 어느 구간·어느 인물인지 묻고, `fixes.md`에서 후보 두세 개를 보인다 |

앞 다섯 줄 중 "구름·풀·별"은 주로 배경 영상(4문단)의 말이고, "천천히·걸음·동작 여럿"은 15블록의 말이다. 시험 C11·C26에서 이 표를 쓰지 않아 실패가 반복됐고, 표를 영상 SKILL 본문으로 옮긴 뒤 해결됐다.
