# 주요 기능 — 지침과 스킬

> 이 키트가 하는 일을 번호로 정리했다. 1~37은 지침(항상 읽힘), 38부터는 스킬(그 작업일 때만 읽힘)이다.
> **[요청]** 은 작업하면서 사용자가 요청한 것, **[추가]** 는 테스트하면서 필요해서 Claude가 넣은 것이다.
> 작업 번호(예: 13번)는 `guides/할일-목록.md`의 번호다.

---

## 1부. 지침

### A. 대화와 작업 정하기
1. **답은 한국어, 프롬프트는 영어.** AI에게 주는 파일은 영어, 사람용 문서와 정본은 한국어. [요청]
2. **할 일 목록 23개.** 사용자 말을 작업 번호 하나로 이해하고, 답 첫 줄에 "13번 실사·인물 영상으로 진행합니다."처럼 밝힌다. [요청]
3. **애매할 때만 확인.** 두 작업으로 읽힐 때만 "이 작업을 할까요?"라고 묻는다. 아니면 사용자가 목록에서 번호로 고른다. [요청 · 매번 묻지 않게 한 것은 추가]
4. **여러 작업을 한 번에 말하면** 순서를 제안하고 첫 작업만 한다. 미룬 작업은 막힌 이유를 한 줄로 알린다. [추가]
5. **시작 문구가 필요 없다.** 컷 번호만 말해도 정본을 읽고 이어 간다. [추가]

### B. 생성 통제
6. **"이미지로 만들어", "영상으로 만들어", "보내"라고 해야만 생성한다.** "그대로"·"좋아"·"진행"은 "보낼까요?" 바로 뒤에도 생성 지시가 아니다. [요청]
7. **사용자가 본 프롬프트만 보낸다.** 보내기 전에 실패 위험과 막는 문장을 먼저 보인다. [추가]
8. **확인은 싸게(이미지 1k·영상 480p), 고해상도는 확정한 뒤에만.** [요청]
9. **같은 실패가 두 번 나면 멈춘다.** 문장을 더하지 않고 샷 나누기·후반 작업을 제안한다. [요청]

### C. 질문하는 법
10. **모호한 말은 구체적인 값으로 바꿔 제안한다.** "구름 더 느리게" → 지금 속도의 절반, "50대처럼" → 주름·피부·머리색. [요청]
11. **"어디서 바꾸나" 표 대신 그때그때 묻는다.** 값 변환 표는 각 스킬 안에만 둔다. [요청]
12. **빠진 것은 한 번에, 제안값과 이유를 붙여 묻는다.** "그대로"면 제안값으로 간다. 같은 것을 두 번 묻지 않는다. [요청]
13. **묻지 않는 것:** 모델·해상도·화면비·소리·저장 폴더·렌즈처럼 정본에 있는 것. [추가]
14. **먼저 짚는 것:** 정본·승인 컷·시작 이미지와 다를 때, 없는 컷 번호, 가리킨 이미지가 대화에 없을 때. [추가]
15. **한 번 정하면 다시 묻지 않는다.** 새 작품 시작 때 질문 14개로 작품 값을 받아 정본에 적는다. [요청]

### D. 방향과 연속성
16. **모든 방향은 화면에 보이는 기준.** 손은 "화면 왼쪽 손, 장에 가까운 쪽"처럼 화면 쪽 + 물건으로 쓴다. 동서남북·인물 자신의 좌우는 쓰지 않는다. [요청]
17. **인물 기준 말은 화면 기준으로 바꾼다.** 카메라를 보는 인물의 "자기 왼손" = 화면 오른쪽. [추가]
18. **반대쪽 카메라면 좌우와 빛 방향이 뒤집힌다고 짚고**, 그 뷰의 조명 문장을 새로 쓴다. [추가]
19. **사건은 동사마다 센다**(나가기도 하나). 한 생성에 3개를 넘으면 샷을 나눈다. 승인 컷에서 가져온 동작은 예외로 그대로 쓴다. [요청]
20. **한 생성에 한 가지만 바꾼다.** [요청]
21. **컷 사이 이어짐.** 앞 컷의 끝 상태가 다음 컷의 시작이 되도록 연속성 표로 맞춘다. [추가]

### E. 프롬프트 만들기
22. **이미지 프롬프트:** 인물 시트, 인물 고치기(옷·머리·나이), 장소, 장소 새 시점, 장소 고치기, 소품, 그림체, 퍼스트 프레임. [요청]
23. **실사 영상 15블록, 배경 영상 4문단.** 연기(표정·손·시선)는 연기 스킬이 따로 맡는다. [요청]
24. **결과 고치기, 1080p 재렌더.** [요청]
25. **"3-1처럼":** 승인된 다른 컷의 동작·표정·색감·카메라를 가져온다. [요청]
26. **고정 문장은 글자 그대로 옮긴다.** 인물 고정 설명, 조명 문장, 승인 컷에서 가져온 줄. [추가]
27. **검사 스크립트.** 보이기 전에 프롬프트를 자동 검사한다(좌표 문장, 손 표기, 참조 태그, 길이). [추가]

### F. 제작 관리
28. **정본 4개**(확정 사항, 에셋 대장, 컷 목록, OK 대장)와 컷 카드·핸드오프. 대화보다 정본이 우선이다. [추가]
29. **Higgsfield 폴더 구조, 승인·거절 기록, 크레딧 기록.** [추가]
30. **장면 컷 나누기:** 블로킹, 180도 선, 커버리지 표. [추가]
31. **마지막 프레임 뽑기, 이어 붙이기(러프컷).** Claude Code 전용. [추가]
32. **컷 사이 색 맞추기:** 재기, 기준 컷에 맞추기, 나란히 비교. Claude Code 전용. [요청]

### G. 문서 구조
33. **항상 읽히는 것과 필요할 때만 읽는 것을 나눈다.** 지침·할 일 목록·must-ask는 항상, 스킬은 그 작업일 때만. [요청]
34. **규칙은 한 곳에만.** 중복은 지우고 주인 파일만 남긴다. [요청]
35. **열면 안 되는 파일을 정한다.** 다른 컷의 카드·핸드오프를 열지 않는다(옛 문장이 프롬프트로 새는 것을 막는다). [추가]
36. **사람용 문서:** 한눈에 보기, 할 일 목록, 세팅, 팀 가이드, 15블록 가이드, 작업별 팁, 이 문서. [요청]
37. **자동 점검 786개와 실제 대화 시험 63개 시나리오.** 키트를 고칠 때마다 다시 돌린다. [요청]

## 2부. 스킬 (9개)

### `project-setup` — 새 작품 시작 (작업 1번)
38. 질문 14개를 표 하나로 한 번에 묻는다. 작품명과 실사/그림체만 필수, 나머지는 기본값이 있다.
39. 대본·콘티가 있는지 한 번만 묻는다. 없다고 하면 다시 묻지 않는다.
40. 답을 받으면 정본 4개의 초안을 만든다(확정 사항에 날짜와 근거, 컷 목록은 장면별 빈 줄).
41. 허락을 받으면 Higgsfield 프로젝트와 폴더(`00 에셋`, `99 시험·보관`)를 만들고 ID를 대장에 적는다.
42. 다음 순서를 안내한다: 그림체 기준 → 인물 → 장소 → 소품 → 컷 카드.

### `production-session` — 대화 진행·컷 카드·핸드오프 (작업 2·16번)
43. **누가 무엇을 고치는지**를 정한다. 총괄 세션은 정본 전체, 컷 세션은 자기 컷 줄의 상태·확정 job 칸만.
44. **총괄 세션:** 정본을 읽고 오늘 할 일 후보를 보인다. 생성/크레딧 칸이 채워진 컷의 핸드오프는 열지 않는다.
45. **컷 세션:** 자기 컷 카드, 컷 목록의 앞뒤 줄, 기준 OK 카드 하나, 마지막 핸드오프만 읽는다.
46. **컷 카드:** 12칸 틀(목표, 저장 위치, 형식, 카메라, 인물, 타이밍, 참조, 고정 설명문, 확정 사항, 위험, 이전 시도, 확정 프롬프트). 질문만 하는 턴에는 만들지 않는다.
47. **핸드오프:** 컷 세션이 끝나면 총괄에게 넘길 내용을 정해진 틀로 쓴다. 총괄은 받아서 정본에 반영한다.
48. **"3-1처럼"(ok-reuse):** 무엇을 가져올지(동작/표정/색감/카메라) 묻고, 가져온 줄은 이름·물건·시간만 바꿔 그대로 옮긴다. 카메라가 반대면 좌우를 뒤집는다. 컷 카드 [7]에 "가져온 OK"를 적는다.

### `shot-design` — 장면 컷 나누기 (작업 3번)
49. 대본이 없으면 컷 목록 내용 줄을 비트로 쓰고, 질문과 같은 답에 설계안까지 보인다.
50. 블로킹 메모(마스터 뷰 기준, 화면 쪽 + 물건), 180도 선, 커버리지 표(마스터·리버스·인서트·리액션)를 만든다.
51. 컷마다 카메라 위치·높이, 화각°·크기, 장소 뷰, 확정 job, 사건 1~3, 길이, 끝 → 다음 시작을 적는다.
52. "리버스"는 마스터의 반대 방향으로 둔다. 맞는 뷰가 없으면 `새 뷰 필요`로 표시한다.
53. 이미 시작 이미지가 있는 컷은 그 화각과 job을 유지하고, 유지·교체를 묻는다.
54. 사용자가 확정하기 전에는 컷 목록을 고치지 않고, 옮길 줄만 보인다.

### `image-prompt` — 이미지 프롬프트 (작업 4~12번)
55. **공통:** 쓰기 전 정보 점검, 참조 이미지가 여럿일 때 권한 문장, 편집 문법(CHANGE / PRESERVE EXACTLY / ONLY CHANGE), 바뀐 값은 "전 → 후"로 보이기. "가짜 같아·AI 같아·너무 매끈해"는 노출 → 선명함 → 피부 → 색 → 너무 깨끗함 순서로 진단하고 첫 원인 하나만 고친다(사실감은 빼기에서 나온다).
56. **인물 시트 새로**(`character.md`): 얼굴·체형·의상·헤어, 고스트 마네킹 의상 패널, 직업 소품 금지 문장. 처음부터 2k.
57. **인물 시트 고치기**(`character-edit.md`): 옷·헤어 하나만, 또는 나이만 바꾼다. 목둘레·지울 옛 옷 칸을 모두 채운다.
58. **장소 마스터**(`location.md`): 빈 공간, 지배 요소, 화면 좌·중·우 랜드마크, 조명 문장(LIGHT LOCK). 반대쪽 카메라 좌우 뒤집기 규칙의 주인 파일.
59. **장소 새 시점**(`location-view.md`): 반대 방향, 같은 쪽 더 가까이, 장소 속 소품을 따로 떼기.
60. **장소 고치기**(`location-edit.md`): 불 켜기·물건 빼기 같은 상태판, 시대·재질 교체(한 번에 한 층), 구도만 빌리기.
61. **소품**(`prop.md`): 재질·사용 흔적·크기(cm + 신체 기준)·무게. 멀리 보이는 것은 시트 없이 컷 문장으로. 차량·간판의 글자는 읽히지 않게.
62. **그림체**(`style.md`): 수채화 같은 매체·기법, 해가 오는 화면 쪽.
63. **퍼스트 프레임**(`first-frame.md`): 카메라가 확정 뷰와 같으면 틀 1(편집), 다르면 틀 2(새 시점). 보이는 인물마다 의상 문장 한 줄.

### `video-prompt` — 영상 프롬프트 (작업 13~15·17번)
64. **쓰기 전 점검표:** 15블록 각각에 들어갈 정보. 렌즈는 묻지 않고 시작 이미지에서 채운다. 대사 여부는 컷 목록에서 본다.
65. **모호한 말 표:** 속도("천천히"는 지금 구간보다 길게), 움직임 추가, 별·새 반짝임, 걸음 나이, "영화같이"(렌즈·심도·빛 대비·카메라 중 하나씩).
66. **사건 세기**의 주인 파일: 동사마다 세고, 3개를 넘으면 샷 나누기 제안. 나가기는 끝 프레임 상태로 쓴다.
67. **실사 15블록**(`live-action.md`): 빈 틀, 그대로 쓰는 문장(입 잠금 등), 길이를 줄이는 순서. 연기 줄을 새로 쓰면 연기 스킬을 먼저 연다.
68. **배경 4문단**(`background.md`): 이미지에 있는 것만 움직이고, 카메라는 사용자가 말할 때만 움직인다.
69. **결과 고치기**(`fixes.md`): 입이 움직임, 휙 돎 같은 증상별 한 줄 처방.
70. **고해상도**(`rerender.md`): 480p 확인본(draft)에서 같은 테이크를 1080p로 올린다. 보내기 전에 견적을 조회한다.

### `acting` — 인물 연기
71. 장면마다 목표와 감정 범위의 양 끝(이 정도면 실패)을 정한다.
72. 몸·손·시선·듣기와 말하기를 구체적인 행동으로 쓴다.
73. 반복 등장 인물의 연기 프로필과 고정 목소리.
74. 작품의 연기 범위(예: 절제)를 넘는 요청은 먼저 짚는다.
75. 질문만 하는 턴에는 열지 않고, 프롬프트를 쓰는 턴에 연다.

### `higgsfield-generation` — 실제 생성·판정 (작업 18~20번)
76. **보내기 전 점검:** 사용자의 생성 지시, 폴더, 해상도, 검사 통과, 처음 쓰는 설정이면 견적.
77. **저장 위치:** 컷 폴더(`3-1 [진행]`) 아래 `승인`·`거절`. 폴더 이름의 상태는 컷 목록과 같게.
78. **보낸 뒤:** 정해진 형식으로 알리고 턴을 끝낸다. 컷 카드 [11]과 컷 목록 생성/크레딧 칸에 기록한다.
79. **판정:** "됐어"면 지시 항목별로 ✔/✘를 보이고 승인·거절을 묻는다. 승인하면 OK 대장에 프롬프트를 그대로 적는다.
80. **크레딧 질문:** 기록된 칸만으로 답한다. 근거(비용 메모, 견적) 없는 숫자는 쓰지 않는다.
81. **숫자 분석**(`qa-metrics.md`): 사용자가 원할 때만 밝기 같은 수치를 잰다.

### `assembly` — 프레임·러프컷 (작업 21번, Claude Code 전용)
82. 마지막 프레임(또는 특정 초의 프레임)을 뽑는다. 영상 길이와 해상도를 함께 보인다.
83. 컷 목록 순서대로 이어 붙여 러프컷을 만든다. 컷마다 해상도·fps·길이와 총 길이를 보인다.
84. 두 컷의 경계(앞 컷 끝 | 다음 컷 시작)를 나란히 비교한다.
85. 원본은 덮어쓰지 않는다. 뽑은 프레임을 다음 컷의 시작 이미지로 쓰기 전에, 이미 확정 시작 이미지가 있으면 교체인지 묻는다.

### `color-continuity` — 컷 사이 색 맞추기 (작업 22번, Claude Code 전용)
86. 기준 컷을 정한다(제안: OK 대장의 OK 이유가 "색감"인 컷). 정본에 "기준 색 컷"으로 적는다.
87. 밝기·색 기울기·대비를 숫자로 재고, 기준 대비 차이를 보인다.
88. 기준 컷에 맞춘 새 파일을 만들고, 맞춘 뒤 다시 재서 전후 숫자를 보인다. 차이가 오히려 커지면 쓰지 말자고 한다.
89. 기준 | 원본 | 맞춘 것을 나란히 놓은 비교 이미지를 만든다.
90. 차이가 너무 크면 후반 보정 대신 그 컷을 다시 만들자고 제안한다. 원본은 덮어쓰지 않는다.
