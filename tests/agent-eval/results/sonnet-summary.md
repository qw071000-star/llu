## 소넷이 Opus보다 더 자주 틀린 곳

1. **컷 세션이 다른 컷 파일을 연다 (5건, Opus 0건).** C02 `cuts/3-1.md`, C12 `cuts/3-1.md`, C13 `cuts/3-1·3-2·3-3.md` + 핸드오프 2건, C14 `cuts/3-1.md`, C17 turn4 `log/3-1_handoff`. Opus는 같은 시나리오에서 자기 컷 카드와 기준 OK 카드 절만 열었다. 소넷은 "기준 OK 카드"를 컷 카드로 읽거나(C02, C12), "이웃 컷과 비교", "이웃 컷에도 같은 값을 쓴다", "이웃 컷의 끝 상태"를 컷 카드를 열라는 말로 읽었다(C13).
2. **승인된 이웃 컷의 인물 자리를 확인하지 않고 지어냈다 (C08).** 연속성 표에 자리가 없을 때 "벤치 가운데"를 제안했다. Opus 2차는 "3-1 시작 이미지 OK 카드의 위치 블록만 가져오자"고 제안했다. 반대로 C13은 이웃 카드를 모두 읽어 "감나무 쪽 절반"을 맞췄다. 즉 규칙을 지키면 정보가 없고, 어기면 맞는다.
3. **길이 WARN을 남겼다 (C10, C12, C18).** Opus 1차는 C10을 4993자로 WARN 없이 만들었다(2차 C12는 5089자 WARN을 이유와 함께 남겼다). 소넷은 15블록 틀을 거의 그대로 채워 5,000자를 넘겼다. 키트는 이유 한 줄이면 허용한다.
4. **앞 답의 오류를 정정하는 줄을 형식에 밀려 빠뜨림 (C17).** 같은 상황의 C18은 "정정:"을 첫 줄에 썼다. 같은 모델이 체인마다 다르게 행동한 것은 키트가 둘의 우선순위를 정하지 않았다는 뜻이다.
5. **불필요한 확인 행동:** 이미 쓴 설정인데 `get_cost` 견적(C17), 정본·OK 카드에 있는 배경을 사용자에게 묻기(C14), 질문 턴에 쓰지 않을 스킬 미리 열기(C08 video-prompt/higgsfield-generation, C12 acting).
6. **고정 문장 충돌 처리 형식이 다름 (C08, C13).** `Except:` 줄을 고정 문장 바로 뒤가 아니라 CHANGE 불릿 안(C08)이나 "It is OPEN:"(C13)로 썼다. 의도는 맞다.

소넷이 Opus와 같거나 나은 곳: "몰라 → 제안값" 처리와 `제안값` 기록(C10), 망원 대 50mm 충돌을 환산표(47°)로 짚음(C10), 75mm = 32°(C02·C12), OK 카드 프롬프트 바이트 일치(C17), 색 문장이 없으면 색 참조 + 권한 좁히기(C13), 2-1 표정 줄 글자 그대로(C14), 핸드오프 [2]에 크레딧 적기(C17, Opus는 못 적음), 재생성 한 줄만 바꾸기(C18).
